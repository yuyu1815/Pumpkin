# 26.2 egress completion gate

## Findings

`crates/pumpkin/src/net/java/mod.rs` の completion waiter は、以前は Drop と正常 flush を同じ `()` で通知していた。そのため、deferred close、cancel、frame/write/flush error、receiver close の破棄が送信成功に見えた。

## Minimal fix

- `OutgoingPacket::Drop` は pending bytes を一度だけ解放し、`Err(())` を通知する。
- TCP writer は frame/write/flush がすべて成功し、flush が完了した後だけ `complete_success()` で `Ok(())` を通知する。
- `start_reconfiguration` と `send_packet_now_data_inner` は `Ok(Ok(()))` だけを成功として扱い、それ以外を失敗として close/return する。
- pending bytes の `checked_add` overflow は panic せず予約拒否にする。release の underflow は ownership 不整合なので checked panic を維持する。
- deferred queue、main queue の sender close、close/cancel の全破棄経路は同じ Drop owner を通る。custom queue framework は追加していない。

## Tests

`crates/pumpkin/src/net/java/mod.rs` の `egress_accounting_tests` に、正常 flush、deferred close、sender close、start-reconfiguration sender close、frame error、closed-peer write path、reservation overflow の回帰を追加した。正常 flush と closed-peer failure は `PendingConnection` の実 `TcpStream` / production `start_outgoing_packet_task` 経路を通し、mock writer/queue は使っていない。

後続 test の完全修飾名:

- `net::java::egress_accounting_tests::successful_flush_notifies_completion_and_writes_on_actual_tcp_path`
- `net::java::egress_accounting_tests::try_kick_flushes_disconnect_frame_before_close`
- `net::java::egress_accounting_tests::deferred_close_releases_bytes_and_unblocks_send_packet_now`
- `net::java::egress_accounting_tests::start_reconfiguration_sender_close_is_failure_and_releases_bytes`
- `net::java::egress_accounting_tests::sender_closed_releases_packet_and_unblocks_waiter`
- `net::java::egress_accounting_tests::writer_frame_error_releases_bytes_and_unblocks_waiter`
- `net::java::egress_accounting_tests::closed_peer_reports_writer_failure_and_releases_bytes`
- `closed-peer flush failure is intentionally not listed as a deterministic TCP assertion; peer shutdown may still flush successfully`
- `net::java::egress_accounting_tests::pending_reservation_overflow_is_rejected_without_wrapping`
