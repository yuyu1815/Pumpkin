# 26.2 signed command vanilla policy

## 判定

`SChatCommandSigned` は、署名失敗時に通常の `SChatCommand` へ降格しない。現在の実装は
26.2 公式 bytecode の観測可能な順序（ACK → parse/signature handling → execute）に合わせ、
安全側の atomic rollback を互換仕様として採用しない。

## 公式根拠（既存 javap artifact）

対象は repo 外の `C:/Temp/minecraft-26_2-inner.jar` を既に `javap -p -c` した出力である。
JAR は実行・コピーしていない。

- `C:/Temp/javap-ServerGamePacketListenerImpl.txt:4480-4500`
  - `handleSignedChatCommand` は最初に `unpackAndApplyLastSeen` を呼ぶ。
  - ACK 更新失敗時は command runnable を呼ばず、`disconnect(CHAT_VALIDATION_FAILED)`。
- 同 `:4502-4565`
  - parse 後に `collectSignedArguments` を呼び、成功した parse result をそのまま
    `Commands.performCommand` へ渡す。再parseしない。
- 同 `:4567-4661`
  - entry は packet order で処理し、name lookup 失敗は `setChainBroken` 後に reject。
  - 各成功 entry の `Decoder.unpack` が chain link を 1 個消費する。
  - 全 entry 後の missing check は reject するが、missing 自体では chain を broken にしない。
  - 同名 duplicate の事前 reject はなく、map value は後の entry で上書きされる。
- `C:/Temp/javap-chat-chain-player.txt:62-183`
  - timestamp の順序を `Instant`（wire millisecond）で確認後、timestamp を保存して RSA verify、成功時に link を advance。
  - out-of-order / invalid signature は chain broken。前 entry の advance は rollback しない。
  - 署名 body 自体へ入る timestamp は epoch-second だが、順序判定は millisecond 精度を保つ。
- `C:/Temp/javap-ServerGamePacketListenerImpl.txt:4661-4695`
  - argument entry が空なら `collectUnsignedArguments`。
  - signable argument が無ければ map は空で、secure session/signature無しでも実行へ進める。
  - signable argument があり、secure decoder のとき null signature は `MISSING_PROFILE_KEY`。
  - secure enforcement 無しの unsigned decoder では unsigned argument として進める。
- 同 `:4446-4510`
  - 通常 unsigned command は `enforceSecureProfile && hasSignableArguments` のときだけ reject。
  - signable argument 無しは secure enforcement 中もこの理由だけでは reject しない。

## Pumpkin policy / 観測可能な結果

`allow_chat_reports=true` を公式の secure-profile enforcement 有効相当、`false` を unsigned
decoder 相当として既存設定に対応付ける。新設定は追加しない。

| case | `allow_chat_reports` | session | entries | 結果 | chain / ACK |
|---|---:|---|---|---|---|
| no-signable signed command | true/false | 無し可 | 空 | execute once | ACK は先に commit、chain link 消費なし |
| signable command, unsigned | false | 無し可 | 空 | unsigned として execute | ACK commit、署名検証・chain消費なし |
| signable command, unsigned | true | 無し/有り | 空 | reject | ACK は残る。missing-key相当で chain はここでは broken にしない |
| signable command, valid entries | true | 有効 | 全 known | execute | ACK先行、entryごとに link を順次 commit |
| signable command, invalid signature | true | 有効 | 全 known | reject | ACK先行、失敗前の entry advance を保持、chain broken |
| signable command, entries present | false | 無し可 | 全 known | unsigned として execute | entry bytes は認証扱いしない。chain消費なし |
| unknown entry | true | 有効/無 | unknown | reject | 公式順で unknown 到達時 chain broken |
| unknown entry | false | 無し可 | unknown | reject | unsigned decoder の chain-break は no-op |
| missing expected entry | true/false | secure時は有効 | 一部 known | reject | 先に読めた entry の advance/ACK は残り、missing 自体は chain break なし |
| duplicate known entry | true/false | secure時は有効/falseは無し可 | same name x2 | 公式上は許可 | secureは packet order で 2 link 消費、falseは unsigned で chain消費なし |
| malformed ACK / bad checksum | true/false | 不問 | 不問 | reject/disconnect | parse・署名検証より前。command は実行しない |

secure mode で signable entry が一つでもある場合、session/key/certificate/expiry の検証を
通らなければ実行しない。reports-disabled の unsigned seam だけが署名検証を省略できる。
したがって「署名 bytes が届いたから未検証のまま secure command を実行する」経路はない。

ただし、Pumpkin の command tree には 26.2 の `SignedArgument`/`CommandSigningContext`
consumer がまだ存在しない。duplicate は公式どおり packet order で全 link を検証・消費するが、
最後の map value を executor の signed-argument context として参照できるとは主張しない。
この文書の duplicate 行は auth/chain policy の一致だけを示し、完全な duplicate execution
compatibility は未解消である。

## 実装点

- `crates/pumpkin/src/net/java/play/chat_command.rs`
  - ACK を最初に `state::apply_last_seen_update`。
  - signable-empty/no-session、reports-disabled unsigned、duplicate、unknown/missing を
    公式の分岐・副作用順で処理。
  - signed/unsigned decoder を問わず、ACK と argument policy を通過した同じ parsed result
    を実行し、event に別 command を注入させない。no-session/reports-disabled path の再parse
    は行わない。
- `crates/pumpkin/src/net/chat/state.rs`
  - `apply_last_seen_update` は既存 clone/validator/checksum を再利用し、ACKを先に commit。
  - `verify_signed_command_entries` は packet order で各 link を即時 advance。後段 failure は
    先段を rollback せず broken にする。chain 順序は millisecond、署名 canonical body は
    epoch-second と分離する。
- `crates/pumpkin/src/net/java/play/chat_ack.rs`
  - 通常 ACK は既存の `chat_lifecycle` lock 内で処理し、signed command と到着順を揃える。

  — exit `0`、3 passed。unknown/missing、duplicate許可、empty signable seam、event mutationを確認。
- `git diff --check -- <owned Rust files>` — exit `0`。

外部 client/server は起動していない。公式 JAR の runtime round-trip、duplicate packet の
実 runtime 結果、plugin event の vanilla 相当は未確認であり、static bytecode と実state-path
の範囲を超えて完全 runtime compatibility とは主張しない。duplicate の signed-argument
context consumer と vanilla の permission/Adventure item predicate も未実装である。
