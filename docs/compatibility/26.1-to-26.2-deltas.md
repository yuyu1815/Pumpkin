### 2. packet/state/ID 差分（実際に比較した範囲）

入力は `assets/packet/26_1_packets.json`（commit `0635b048b579a756648ed253a65955ab026aeef5` 由来、SHA-256 `6ade15d40dbbb872affa0537356dea1a62a8b8fbca1ca24f21a9749db835dd7a`）と現行 `assets/packet/26_2_packets.json`（SHA-256 `430b59553e9dbf6a54aecf389436db94dc1617af98e295b97d2dd2edbe5c1d4d`）を JSON として比較した。

| state/direction | 26.1 | 26.2 | 差分 |
|---|---:|---:|---|
| status serverbound/clientbound | 2 / 2 | 2 / 2 | ID `0..1` は同じ |
| login serverbound/clientbound | 5 / 6 | 5 / 6 | ID `0..4` / `0..5` は同じ |
| configuration serverbound/clientbound | 10 / 20 | 10 / 20 | ID `0..9` / `0..19` は同じ |
| play serverbound/clientbound | 69 / 141 | 69 / 141 | ID `0..68` / `0..140` は同じ。local asset の名前差は別source系として扱う |
| handshake | local 26.1 Pumpkin asset は `handshake.serverbound` 1 entry、全体 `257` entries。別途 `tools/compat-data` の Prismarine 26.1 summary は `handshaking/serverbound` 2 entries（ID `0,254`）を報告 | 26.2 local asset は `handshake.serverbound` 1 entry、全体 `256` entries | local 26.1/26.2 の通常 handshake entry はともに ID `0`。Prismarine summary の ID `254` は別 source representation として保留し、通常 handshakeの `intention=0` へ暗黙統合しない |

同一 state/direction で **numeric ID が変わった packet は確認できなかった**。local Pumpkin assets の concrete name comparator は次の6件を出した: login/clientbound ID `2` `game_profile→login_finished`、play/clientbound ID `65` `chat→player_chat`、ID `73` `move_player_rot→player_rotation`、ID `105` `set_carried_item→set_held_slot`、play/serverbound ID `15` `command_suggestions→command_suggestion`、ID `64` `spectate_entity→teleport_to_entity`。ID `62` は local 26.1/26.2 とも `minecraft:spectator_action` である。

一方、pinned Prismarine 26.1 `protocol.json` は `play/serverbound/62 = spectate_entity` で、同 pin に26.2 schemaは無い。したがって旧候補 `spectate_entity → spectator_action` は 26.1→26.2 の実版差として確定できず、少なくとも Prismarine schema と Pumpkin packet asset の**ライブラリ／source naming差**である可能性が高い。異なる source系の名前を serverの誤り、payload不変、codec semantic同値と断定しない。`ALW-2601-REPLAY-PACKET-LABEL-62` は `proposed/disabled` に戻した。local assets の他の名前差も同様に自動許容しない。26.2 input/generated の state/direction/ID は既存監査で `256/256` 一致（`docs/compatibility/26.2-protocol-audit.md`）している。handshake/legacy も source representation が一致しないため、許容規則へ自動昇格しない。

**field/state の実比較範囲:** 全 packet の field wire layout を一次 JAR と突合したわけではない。既存 `tools/compat-data/data/26.1/protocol-summary.json` と 26.2 summary、および `crates/pumpkin-protocol` の既存 codec 読解で、次だけを確認した。

- `configuration/clientbound/registry_data`: registry id string、entry 配列、entry key、optional anonymous NBT。
- `configuration/clientbound/update_tags` 相当: tag category、tag 名、entry ID 配列。
- `play/serverbound/configuration_acknowledged`: empty packet。
- login/configuration/play の state transition と ID は既存 harness で synthetic framing のみ確認。

従って「IDが同じ」から field schema/値/vanilla client acceptance が同じとは言わない。未知 packet を 26.1 decoder が無条件に捨ててよい根拠はない。

### 4. item components / recipes / tracked data

- official 26.1 release notes は data-driven registry、recipe field syntax、world storage changes を明記。26.2 release notes は `minecraft:sulfur_cube_content` component、Sulfur Cube archetype registry、Living Entity の `HurtByTimestamp` removal を明記。
- `assets/data_component.json`: `110 → 111`、追加は `minecraft:sulfur_cube_content`。既存 component ID の再番号化もあるため、名前だけで整数 ID を流用しない。
- `assets/tracked_data/26_1_tracked_data.json` → `26_2_tracked_data.json`: entry `225 → 227`。`abstract_cube_mob` と `sulfur_cube` が追加、`slime`/`magma_cube` の tracked field set が 26.2 に変わる。新 entity があるという差だけで、旧 entity の値/状態を無視してよいことにはならない。
- data pack source の JSON 件数（`assets/datapacks/<version>/data/minecraft` の全 JSON）: `26_1=1,140`、`26_2=7,664`。26.2 には `recipe=1,864`、`advancement=1,688`、`loot_table=1,356`、`sulfur_cube_archetype=12`、`villager_trade=388`、`trial_spawner=28` 等が含まれる。26.1 の `recipe` directory はこの asset snapshot には無く、recipe/registry boundary が同一とは扱えない。
- 既存 registry audit は 26.2 source recipe の codegen accepted count `1,585`、result components `17`、special/unsupported recipe `23` を報告している。これは 26.2 の現状監査値であり、26.1との差を理由に components を落としてよい証拠ではない。

### 5. registry / tags / known packs

- 26.1 release notes の Data Pack 101.1 と 26.2 release notes の Data Pack 107.1 は、registry/data schema の世代差を示す。
- datapack top-level の比較では tags `758 → 796`、damage_type `50 → 51`、jukebox_song `21 → 22`、worldgen `65 → 1,032`。26.2 は 26.1 に無い registry/data directory を多数追加している。
- 現行 codegen/runtime の `SYNCED_REGISTRIES` は 26.2 用に `29` registry。既存 audit では generated source entry 合計 `397`（`chat_type` は raw 注入で source `7` → generated `8`）を確認しているが、公式 vanilla client の全 Registry Data decode/acceptance は未確認。
- Known Packs の synthetic harness は `known_pack_reply=true` を観測しただけで、個数/tuple、Registry Data の NBT value、Update Tags の全値、vanilla client acceptance は未確認。
- よって `registryを全部skip`、未知 registry を無条件に空にする、Known Packs を version文字列だけで pass にする、は明確に禁止する。

### 6. world format / gameplay

26.1 official release notes の World Storage section は、default dimensions を `dimensions/minecraft/{overworld,the_nether,the_end}` に移動、player storage を `players/` に移動、data を namespace 化、`chunks.dat`/map/idcounts の rename、level.dat の difficulty/dragon/weather/world-gen/world-clocks 変更を記載している。26.2 release notes は「26.1より前の一部 world upgrade を高速化」と記載するが、旧 world を無条件に 26.2 とみなす根拠ではない。

repo の確認範囲:

- `crates/pumpkin-world/src/world_info/mod.rs`: current `DataVersion=4903` 上限、level version `19133` の保護。
- `crates/pumpkin-world/src/level.rs`: 26.2 canonical dimension path と旧 Anvil path の選択。
- `crates/pumpkin-world/src/world_info/data_files.rs`: 26.x の root/dimension data layout の読込。
- `docs/compatibility/26.2-world-audit.md`: level.dat/data-file fixture と未確認範囲。

実 vanilla 26.1 world を 26.2 へ変換し、公式 26.2 client/server が受理した証拠はない。DataVersion、level version、dimension/registry、block entity、scheduled tick、seed、component のいずれかが欠けた場合は version差ではなく未検証/実バグとして扱う。
