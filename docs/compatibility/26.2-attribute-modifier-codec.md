# 26.2 `attribute_modifiers` data-component codec

## Findings

- `DataComponentCodec<AttributeModifiersImpl>::deserialize` previously consumed every entry and returned `Cow::Borrowed(&[])`. Any item patch or Adventure exact component matcher therefore lost the complete component on decode and encoded count `0` afterward.
- The implementation now retains every wire entry in the existing `AttributeModifiersImpl::attribute_modifiers` model. `Modifier` owns a `Cow<'static, str>` resource ID and a `ModifierDisplay` value (`Default`, `Hidden`, or raw-NBT `Override` component). The item-NBT path also accepts the official named fields (`type`, string operation/slot, and typed display object) while retaining the prior numeric form as a read-compatibility fallback.
- The codec preserves attribute registry ID, modifier resource ID, IEEE-754 `double` amount bits, operation, equipment-slot group, display type, and override component payload.

## Official 26.2 evidence

Read-only disassembly from `C:/Temp/minecraft-26_2-inner.jar`:

- `C:/Temp/javap-ItemAttributeModifiers-26_2.txt`: `ItemAttributeModifiers.STREAM_CODEC` is a VarInt-length-prefixed list of `Entry` values.
- `C:/Temp/javap-ItemAttributeModifiers-Entry-26_2.txt`: an entry is the attribute holder, `AttributeModifier`, `EquipmentSlotGroup`, and `Display`.
- `C:/Temp/javap-AttributeModifier-26_2.txt`: `AttributeModifier.STREAM_CODEC` composes `Identifier`, `ByteBufCodecs.DOUBLE`, and `Operation`.
- `C:/Temp/javap-AttributeModifier-Operation-26_2.txt`: operation IDs are `0=ADD_VALUE`, `1=ADD_MULTIPLIED_BASE`, `2=ADD_MULTIPLIED_TOTAL`.
- `C:/Temp/javap-Attribute-registry-26_2.txt`: `Attribute.STREAM_CODEC` uses the `ATTRIBUTE` registry holder codec.
- `C:/Temp/javap-ItemAttributeModifiers-Display-26_2.txt`: display IDs are `0=default`, `1=hidden`, `2=override`; the override carries a chat component.
- `EquipmentSlotGroup` in the same official output uses IDs `0..10`: `any`, `mainhand`, `offhand`, `hand`, `feet`, `legs`, `chest`, `head`, `armor`, `body`, `saddle`.

Pumpkin's current 26.2 attribute registry is `pumpkin_data::attributes::Attributes::ALL`, generated with IDs `0..39`; decode validates the received registry ID against that current table rather than using the 26.1 schema as an authority.

## Validation and retention

- Negative modifier counts are rejected. The wire count is the official non-negative VarInt list length; encode rejects lengths that cannot fit an `i32` VarInt.
- Unknown attribute registry IDs, operation IDs, slot IDs, and display IDs are rejected instead of mapping through an unknown-enum fallback and losing type information.
- Modifier IDs are validated with the existing `pumpkin_util::identifier::Identifier` parser and retain the original resource-location string for re-encoding.
- Amounts use the official raw `DOUBLE` codec. Non-finite values are accepted because the official `AttributeModifier` constructor and `ByteBufCodecs.DOUBLE` impose no finite-only check; the fixture asserts NaN bit preservation and Infinity acceptance.
- Display override payloads use the existing 26.2 unnamed NBT codec used by `ComponentSerialization.STREAM_CODEC`. `End`/missing override payloads are rejected; raw payload tags remain in `ModifierDisplay::Override`. Item-NBT writes use the official display object (`type: hidden|override`, with `value` for override), omit the default/`any` fields, and read the older numeric/string representation for compatibility.
- `AttributeModifiersImpl::read_data` / `write_data` retain the typed component when Adventure exact matchers pass through the existing data-component conversion path.

## Tests and checks

- `codec::data_component::attribute_modifier_tests::independent_wire_round_trip_preserves_all_modifier_fields`: independent bytes, three entries, all display variants, registry IDs, resource IDs, operations, slots, finite/NaN/Infinity amounts; asserts `decode -> encode` byte equality and typed values.
- `codec::data_component::attribute_modifier_tests::attribute_modifier_rejects_invalid_counts_ids_and_enums`: negative count, unknown attribute, invalid resource ID, operation, slot, and display rejection.
- `codec::data_component::adventure_predicate_tests::nested_attribute_modifier_exact_matcher_round_trips_wire_and_type`: nested Adventure exact matcher uses the same `AttributeModifiersImpl` codec, asserts typed NBT value, and asserts independent bytes decode/encode equality.

## Scope and remaining lossy codecs

This change is limited to `AttributeModifiersImpl`, its required data-model fields, the WASM attribute-modifier caller needed by the type change, the protocol/data tests, and this compatibility note. Because item NBT modifiers now survive decode, the existing living/player/attack attribute callers can consume them; those callers were traced and no calculation algorithm was changed.

Known unrelated lossy paths remain unchanged: `TooltipDisplayImpl` still discards its standalone component fields, several marker/placeholder component codecs still write their fixed placeholder values, and multi-entry Adventure matcher NBT compounds remain subject to the existing `HashMap` iteration order when re-encoded. Runtime client acceptance, older-than-26.2 packet compatibility, and the full outbound signed-chat plan are not claimed.
