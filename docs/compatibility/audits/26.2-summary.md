# Minecraft Java 26.2 並列8分野監査・相互レビュー集約

- 対象: Java Edition 26.2 / protocol `776` / world data version `4903`
- 対象文書: `26.2-network.md`, `26.2-world-storage.md`, `26.2-inventory.md`, `26.2-player-entities.md`, `26.2-blocks-ticks.md`, `26.2-registry-data.md`, `26.2-chat-permissions.md`, `26.2-runtime.md`
- 目的: 8分野の並列出力を重複排除し、確度・優先度・後続実装の依存を統一する。今回は実装を開始しない。
- 結論: **P0 1件、P1 24件、P2 10件の主発見を回収した。追加候補8件を含む文書上の単位は43件、同一根拠を跨ぐ明白な重複（signed commandのunchecked decode/auth）を1件に統合した集約clusterは42件。** ただし、P0/P1を含む大半は静的根拠であり、実機・vanilla client・再起動・悪意wire入力による再現済み件数ではない。

#### 相互レビューで断言を弱めたもの

- `NET-FRAME`のcompressed trailing/desynchronizationは、decoderのdecompressed length一致だけでは不十分という設計懸念は維持するが、`BufReader` read-aheadとzlib stream終端の実観測がないため、**「全compressed trailingで確実にdesync」とは断定しない**。
- `INV-01`は制御フロー上の増殖候補としてP0維持。ただしvanilla clientがその厳密な部分stack状態を生成することは未確認で、実機reproductionではない。
- `PLY-MOVE`は既存のteleport ack、finite/NaN、clamp、broadcastを確認したため「移動入力を全く検証しない」ではなく、**衝突・速度・vehicle authorityのserver-side acceptanceが不足**とする。
- `PLY-TRANSFER`はplayer source detach自体は実装されている。欠落はdestination tracker/pairingとnon-player world ownershipであり、全transferが必ず不可視になるとは断定しない。
- `R3` registry whitelist、`R2` dimension fallback、`R1` recipe components、`R4` item component valuesは、source/generated件数やTODOの静的根拠はあるが、公式clientのdecode/acceptance未確認なのでP1候補/semantic gapとして優先検証する。ID連番一致を意味同一性の証拠にしない。

### 3. 分野別の主な発見（上位12件以外）

- **network**: Playの`configuration_acknowledged`がserver-issued `CStartConfiguration`なしでもConfigへstoreされる (`crates/pumpkin/src/net/java/play/configuration_acknowledged.rs:6-12`, dispatch `mod.rs:1364-1366`)。P2。compression thresholdの既存`>=`修正は重複計上しない。
- **world-storage**: Windows既存`.mca`のtemp→rename置換 (`chunk/format/anvil.rs:460-490`)、canonical/legacy二重layout (`world/level.rs:174-190`, `world_info/data_files.rs:236-407`)、直接File::create/fsync不足 (`world_info/data_files.rs`, `chunk/format/anvil.rs:350-490`)。P1/P2。負座標写像はprobe済みで問題発見ではない。
- **inventory**: `INV-02`は`Player::on_slot_click` (`entity/player.rs:5773-6172`)がrevision mismatchを検出してもmutation後resyncするだけで、changed-slot/cursor hashを操作前比較しない。`INV-03`はremainder、component、transmuteのinput/material、recipe-book max stackを分けてtestする。`INV-04`はhopper5枠に対し`rows*9`境界。`INV-05`はequipment broadcastとclose window-idを分ける。
- **player/entities**: Elytra/gliding (`living.rs:1404-1406` TODO)、respawn safe spawn/state sync (`world/mod.rs:4346-4632`, TODO `:4614`)はP2/未実装仕様。disconnectの通常cleanupは確認でき、欠落とは数えない。
- **blocks/ticks**: `TICK-02`は`get_tick_data`のscheduled側が`active_chunks`を見ず、loaded-only chunkでも進める (`pumpkin-world/src/level.rs:580-600`)。`PST-01`は`block/entities/piston.rs:256-295`でpushed stateが保存されずAIR復元。powered/activator railとlava `BlockFromToEvent` identityは追加未優先候補。
- **registry/data**: source/generated IDは blocks `1196`, items `1537`, entities `158`, components `111`で各連番・重複0。registryは29 whitelist/source total397（`chat_type.raw`の注入+1）だが、NBT schema/value・Known Packs semantic acceptanceは未確認。recipe source `1585`、特殊23、result components17の既存scan根拠あり。
- **chat/permissions**: Bungee forwarded IP破棄 (`net/proxy/bungeecord.rs:46-77` → `login_start.rs:53-66`)でIP banがproxy addressを見るP1。offline UUIDは`net/mod.rs:74-76`のSHA-256先頭16 bytesで、vanilla `OfflinePlayer:<name>` v3との互換差をP2。Bedrock command treeのpermission level `Any`固定はP2だが、dispatcher実行時permission bypassとは断定しない。
- **runtime**: `Server::shutdown` (`server/mod.rs:747-751`)がTaskTrackerを無期限waitしてからworld saveするため、hung task時の停止遅延候補RT-01。client/listener trackerのclose/waitという既存防御があるためP2候補に留める。

### 4. 正常経路・既存防御として集約から除外したもの

- protocol mapping `256/256`、protocol `776`、world `4903`、strict synthetic play/status/login/configuration/first-playable traceは既存資料の成果として再利用。ただしvanilla client互換・registry semantic equalityの証拠には昇格させない。
- compression threshold境界修正、Anvil header underflow修正 (`334b37ade`)、disk block entity resume (`844e2871e`)、world-gen layout read対応 (`7f369c4b5`)、player hand-swap変更は既知/既存変更として二重計上しない。
- permission dispatcherのserver-side check、online mode/encryption config validation、Bungee/Vine/Velocityのsecret/signature検証、teleport confirmation、normal disconnect cleanupは確認できる防御である。
