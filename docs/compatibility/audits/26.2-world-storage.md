### WLD-01: 既存 Anvil region の置換失敗（P1）

**該当箇所**

- `crates/pumpkin-world/src/chunk/format/anvil.rs:460-490` `AnvilChunkFile::write_all`
  - `path.with_extension("tmp")` に書き、`flush()` 後に `tokio::fs::rename(temp_path, path)`。
- `crates/pumpkin-world/src/chunk/format/anvil.rs:513-534` `ChunkSerializer for AnvilChunkFile::write`
  - `WriteAction::All` は既定設定 `AnvilChunkConfig::write_in_place = false` でも選択される。
- `crates/pumpkin-world/src/chunk/io/file_manager.rs:321-417` `ChunkFileManager::save_chunks`
  - region ごとに save し、エラーは `Level::write_chunks`/`worker_logic::io_write_work` でログへ送るだけ。
- 対照: `crates/pumpkin-world/src/world_info/anvil.rs:358-371` `replace_level_dat` は既存 destination を Windows 用に削除して再 rename する。region には同じ処理がない。

**入力/状態**

- 既存の `region/r.0.0.mca` があり、dirty chunk のサイズ変更などで `WriteAction::All` になる状態。
- `write_in_place=false`（`crates/pumpkin-config/src/chunk.rs:30-38`、Default は false）。
- Windows filesystem。今回の実行環境の確認値は `platform=Windows-10-10.0.26200-SP0`。

**期待 vs 現状**

- 期待: 完全な新 region を一時ファイルへ書き、既存 `.mca` を原子的に置換し、失敗時は旧 region を保持しつつ明示的に失敗する。
- 現状: Windows の通常 `rename` は既存 destination を置換しないため `AlreadyExists` になり得る。`write_all` は error を返すが、サーバー側は `Failed to save chunks` のログのみで稼働を継続する。`r.<x>.<z>.tmp` は残り得る。旧 region はそのままだが、今回の変更と以後の更新は再起動後に失われる。

**影響/確度/根拠**

- 影響: 既存 region の autosave/manual save が継続的に永続化されず、ユーザーの block/entity/tick/light 変更を失う。新規 region の初回作成だけは destination 不在なので通る可能性がある。
- 確度: **高（静的確定）**。Windows の既存 destination rename 失敗は、既存 level.dat 修正が必要だった理由と同じ OS semantics。実 region save は制約により未実行。
- 出典/既知事項: `docs/compatibility/26.2-world-audit.md` と `26.2-integration.md` は level.dat の既存 destination 修正を確認済みと記録するが、region replacement は対象外。upstream `334b37ade` は region header underflow の修正であり、rename 問題は直していない。

**最小再現/テスト案**

1. ユーザーデータではなく `tempfile::TempDir` 内で既存 `r.0.0.mca` と dirty chunk を作る。
2. `AnvilChunkConfig { write_in_place: false, .. }` で二回 `save_chunks` し、Windows で二回目の結果、exit/error、`.tmp` 残留、再読込値を確認する。
3. POSIX/Windows の両方で旧ファイル hash と新ファイルの再読込を比較し、途中 I/O failure 注入時に旧ファイルが読めることも確認する。

**修正パス**

- `level.dat` と同じ destination replacement helper を region にも適用。ただし delete-then-rename は電源断窓を広げるので、Windows では replace-capable API/rename strategy を選ぶ。
- temp 名を region 単位で一意にし、file flush/fsync と directory durability を明示する。失敗を `save_chunks` から server shutdown 判定まで伝播させる。

### WLD-02: corruption recovery が Missing と混同される（P1）

**該当箇所**

- `crates/pumpkin-world/src/chunk/format/anvil.rs:535-604` `AnvilChunkFile::read`
  - location の範囲と length underflow は検査するが、参照 chunk の NBT/compression は後段。
- `crates/pumpkin-world/src/chunk/io/file_manager.rs:78-112` `ChunkSerializerLazyLoader::read_from_disk`
  - region parse error は serializer 初期化失敗として返る。
- `crates/pumpkin-world/src/chunk/io/file_manager.rs:257-318` `ChunkFileManager::fetch_chunks`
  - serializer read error を batch の最初の coordinate への `LoadedData::Error` 一件として送る。他の座標は送られない。
- `crates/pumpkin-world/src/chunk/format/anvil.rs:756-812` `AnvilChunkFile::get_chunks`
  - compression/decode error は `LoadedData::Error((chunk, err))` として個別に返す。
- `crates/pumpkin-world/src/chunk_system/worker_logic.rs:129-174` `io_read_work`
  - `LoadedData::Missing(pos) | LoadedData::Error((pos, _))` の両方を空の `ProtoChunk` として処理する。
- `crates/pumpkin-world/src/chunk_system/worker_logic.rs:200-225` `io_write_work`
  - 再生成した chunk を通常の save 経路へ送る。

**入力/状態**

- 例1: location/sector 範囲は読めるが、chunk payload の compression stream または NBT が壊れている。
- 例2: 一つの region entry が length 0/不正圧縮/不正 NBTで、同じ region の別 chunk は正常。

**期待 vs 現状**

- 期待: missing（未生成）と corruption（存在したが読めない）を区別し、破損ファイルを quarantine/backup して管理者へ通知し、原データを暗黙に上書きしない。region header が一部不正でも有効 entry を可能な限り salvage する。
- 現状: payload decode error は生成対象へ降格する。再生成された chunk が save されると、壊れた slot の旧データを置き換え得る。region 全体の `read` エラーでは batch の先頭だけが error になり、残りの requested chunks は応答されず、worker 側も error を regeneration として扱う。

**影響/確度/根拠**

- 影響: corruption の検知証跡と旧 payload を失ったうえで、建築物、block entity、構造、地形を新規生成で置換する可能性。壊れた一 entry が region の他 chunk の load を止める。
- 確度: **高（制御フロー上確定、実ワールド未再現）**。`Error` と `Missing` の同一 match arm は明示的に確認できる。
- 既知問題との区別: upstream `334b37ade` で `sector_offset < 2` と chunk length underflow は修正済み。本 finding はその後の error policy/recovery の問題であり、既知修正済み項目を再報告していない。

**最小再現/テスト案**

1. TempDir に最小の 3-sector region を作り、合法な location header の payload を不正 zlib/LZ4 または切断 NBTにする。
2. `AnvilChunkFile::read` は成功、`get_chunks` は `LoadedData::Error` になるケースを作る。
3. `io_read_work` の test double で同一 coordinate が空 Protoへ変わらず corruption error として上位に届くこと、save が旧 slot を変更しないことを固定する。
4. 別 entry だけ不正な region で、正常 entryを salvage できるかを確認する。

**修正パス**

- `Missing`/`Corrupt`/`IoError` を型として分離し、corrupt は生成・save に流さない。
- region header の entry 単位検証、sector overlap/範囲/圧縮/NBT decode の salvage 方針を実装し、元 `.mca` の backup/quarantine と warning に chunk/region 座標を含める。

### WLD-03: chunk NBT round-trip が損失的、破損入力に fail-closed でない（P1）

**該当箇所**

- `crates/pumpkin-world/src/chunk/format/mod.rs:167-414` `ChunkData::internal_from_bytes`
  - 読むのは `xPos/zPos/yPos`、sections の block/biome/light、3 heightmap、ticks、block_entities、`isLightOn`、status、`InhabitedTime`、Pumpkin/Bukkit custom data 等に限定される。
  - `blending_data` は常に `None` (`:405`)。
- `crates/pumpkin-world/src/chunk/format/mod.rs:418-573` `ChunkData::internal_to_bytes`
  - 上記の subset のみを書き、入力 NBTの未知/未モデル化 tag をコピーしない。structure metadata、carving/post-processing 系を保持する処理はこの codec に存在しない（`git grep` でも該当 encode/decode なし）。
- `crates/pumpkin-world/src/chunk/format/mod.rs:232-261` は BlockLight/SkyLight を配列長検証なしで `Full` にする。
- `crates/pumpkin-world/src/chunk/format/mod.rs:263-293` と `crates/pumpkin-world/src/chunk/palette.rs:285-390` は palette/packed data の短縮をエラーにせず、足りない word を 0/既定値で埋める。
- `crates/pumpkin-world/src/chunk/mod.rs:196-243` `ChunkHeightmaps::set/get` は heightmapを37 long前提で indexするが、load側は配列長を検証せずそのまま保持する。
- `crates/pumpkin-world/src/chunk/format/mod.rs:816-850` `LightContainer::get` は Full data が1024 bytesである前提で indexするが、load側は長さを検証しない。

**入力/状態**

- 正常な 26.2/旧 1.21.9 world chunk を Pumpkin が loadし、何らかの理由（unload/autosave/shutdown）で saveする。
- あるいは truncated heightmap/light/packed paletteを含む既存 regionを読む。

**期待 vs 現状**

- 期待: 既知の Java chunk tag を decode/encode で保持するか、未対応 tag を opaque NBT として保存する。配列長・bits/palette index・light arrayを検証し、不正なら corruption error として停止する。
- 現状: load→saveだけで未対応 tagが消える。`blending_data` は code上必ず消える。短い配列は拒否されず、後続の heightmap/light参照で panic または既定値への黙った置換になり得る。`ChunkData::internal_from_bytes` は chunk `DataVersion` 自体も検証せず、範囲外 payloadを読み、save時に `4903` へ書き換える。

**影響/確度/根拠**

- 影響: 古い world の blending、structure continuation/metadata、将来の生成・locate・再接続に必要なデータを chunk save で消失。悪意/偶発的な malformed NBT は server crashまたは地形・biomeの黙った破損へつながる。
- 確度: **高（lossy encode と長さ未検証は静的確定、公式 chunk fixtureでの実影響は未検証）**。
- 既知問題との区別: upstream `844e2871e` は disk chunkから block entitiesを `ProtoChunk`へ引き継ぐ修正済み。本 finding はその修正済み block entity経路とは別に、未モデル化 tagと配列検証を指摘する。

**最小再現/テスト案**

1. NBT fixtureに `blending_data`、`structures`、未知 compound、通常の sections/heightmapsを入れ、`internal_from_bytes`→`internal_to_bytes`→NBT比較を行う。
2. Heightmaps を0/36/38 longs、lightを0/1023/1025 bytes、packed dataを不足/過剰、palette indexを範囲外にした fixtureで、panicせず明示的 corruption errorになることを確認する。
3. 26.2 official fixture（JAR/worldはrepo外、hashのみ文書化）で非空 block/biome palette、negative chunk、heightmap 37 longs、light 2048 bytes、block entity、statusを一周させる。

**修正パス**

- `ChunkData` に必要な vanilla fields（少なくとも blending/structure/post-processing の保存表現）を追加するか、未対応 root/section tags を opaque NBT として保持する。
- `ChunkParsingError` へ厳格な shape/version validationを追加し、`from_palette_and_packed_data` の default補完を corruption入力の通常経路に使わない。

### WLD-05: save atomicity/durability と並行 snapshot（P2）

**該当箇所**

- `crates/pumpkin-world/src/chunk/format/anvil.rs:350-458` `write_indices`
  - in-place時に location/timestamp headerを先に書き、その後 payloadをsectorへ書く。temp file/rollback/fsyncなし。
- `crates/pumpkin-world/src/chunk/format/anvil.rs:460-490` `write_all`
  - temp+renameだが file/directory fsyncなし。なお WLD-01の既存destination問題もある。
- `crates/pumpkin-world/src/world_info/data_files.rs:145-171,351-407,480-710`
  - game_rules/world_gen_settings/clocks/weather等を `File::create` で直接 truncate/write。partial write後のold-file fallbackはない。
- `crates/pumpkin-world/src/world_info/anvil.rs:431-500`
  - level.dat自体は temp replacementだが、 ancillary data file の save error は `error!` を出して `Ok(())` を返す。
- `crates/pumpkin-world/src/chunk/io/file_manager.rs:333-365`
  - dirty flagを snapshot/clearしてから `update_chunk` serialization。並行 mutationは次回 dirtyに残る設計だが、sections/heightmap/light/entitiesを同一時点で凍結する transaction/snapshotではない。

**入力/状態**

- `write_in_place=true`、停電/kill/I/O failureがheader writeとpayload writeの間に発生。
- data/minecraft の既存 fileを保存中にprocess終了。
- save serialization中に block/biome/light/heightmap/block entity が別threadから変更。

**期待 vs 現状**

- 期待: 全ての永続化対象が old-or-new のいずれかとして読め、失敗を返し、chunk snapshotは同一logical tickの整合した状態。
- 現状: in-place header先行で旧payloadとの対応が壊れ得る。直接 createは途中で空/切断 fileを残す。ancillary errorはworld save成功に見える。個別lockはあるが、codec全体の一貫snapshotではない。

**影響/確度/根拠**

- 影響: 停電・強制終了・ディスクfullで region/world metadataの破損、古い/新しい状態の混在、直前tickの一部だけ保存。
- 確度: **高（atomicity不足は静的確定、停電タイミングの実再現は未実施）**。

**最小再現/テスト案**

1. temp-only file system wrapperまたは test hookで header/payload/data-file write後に `Error` を注入する。
2. 再起動相当の新 managerで、旧fileが読めるか、`.tmp`/partial fileを誤採用しないか確認する。
3. 並行 writer/mutatorを実行し、保存後にblock/biome/light/heightmap/block entityのcross-field invariantを検査する。

**修正パス**

- Anvil/linear/metadata/data filesを共通の temp-write → flush → fsync → replace → directory fsync へ寄せる。
- in-placeは安全性を証明できるまで無効化、または region全体 copy-on-write にする。
- chunkのimmutable snapshot/versionを取得して serializeし、snapshot versionとdirty clearをcommit時に照合する。全 ancillary errorを上位へ返す。

```text
 0  -> region 0,  local 0
 31 -> region 0,  local 31
 32 -> region 1,  local 0
```

これはJavaの floor-div/rem-euclid と一致する。現行 active testに負座標 Anvil round-trip fixtureはないため、**写像は確認済み、disk round-trip/sector shiftは未確認**とする。

### Height / biome / palette / light

- 26.2の想定 sectionは世界min Yとheightから組み立てられるが、`internal_from_bytes` は見つかった最大 section Yまでだけを動的に作る。`yPos`より下の sectionは silently skip、duplicate/不正Yも厳格拒否しない。
- Block paletteは vanilla compound (`Name`/`Properties`) を state IDへ解決し、biome paletteは文字列名をu8へ解決する既存テストがある。`to_disk_nbt` は block compound/biome stringを書き戻す。正常な小 fixtureの意味論は部分確認のみで、26.2 official non-empty paletteの完全round-tripは未確認。
- `PalettedContainer::from_palette_and_packed_data` は短いpacked dataを0で補い、範囲外indexをdefaultへ落とす。これは corruption recoveryではなく黙ったデータ変換になる。
- heightmapは37 longs、lightは1024 bytesという前提が利用側にあるが、load時のlength validationがない。WLD-03の最小fixtureを優先する。

## サーバー側 load/save 呼出し監査

1. `Level::from_root_folder` (`crates/pumpkin-world/src/level.rs:154-199`) が dimension folderと `ChunkSaver`/`EntitySaver`を作成する。
2. `GenerationSchedule::create` (`chunk_system/schedule.rs:117-178`) が `io_read_work`/`io_write_work`を常駐させる。
3. `worker_logic::io_read_work` (`:129-174`) が `Level::chunk_saver.fetch_chunks`を呼ぶ。read errorの扱いはWLD-02参照。
4. `GenerationSchedule::save_all_chunk` (`schedule.rs:920-962`) と `process_unload_queue` (`:842-918`) が dirty/Protoを `io_write`へ送る。
5. `worker_logic::io_write_work` (`:175-225`) が `Level::chunk_saver.save_chunks`を呼び、完了後に per-position IOLockを解放する。
6. `Level::write_chunks` (`level.rs:845-862`) と entity相当 (`:865-881`) は save errorをlogへ変換する。
7. shutdown (`level.rs:365-424`) は task/threadを待って chunk serializer barrierを通す。schedule側にも shutdown時 `save_all_chunk(true)` (`schedule.rs:1257-1271`) があるため、chunkをshutdown時に全くsaveしないという所見は採用しない。ただし下層の save failure/atomicityは解決しない。

`ChunkFileManager`は同一 pathに `Arc<RwLock<S>>`を共有しており、同一regionのserializer write/readの同時実行を抑制する設計自体は確認できる。一方、watcher eviction、複数level instance、path alias（canonical/legacy同時利用）を跨ぐ process-wide lock ではないため、migration中の二重loaderを許容しない運用が必要。
