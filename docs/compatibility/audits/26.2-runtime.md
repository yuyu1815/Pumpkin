# Minecraft Java 26.2 runtime・task lifecycle 補完監査

- 対象: Java Edition 26.2 / protocol `776` / world data version `4903`
- 種別: runtime 分野の欠落補完。静的読解のみ。正式 Rust code/config は変更していない。
- 判定: 接続 task/client task の協調停止経路は存在するが、server-owned task の終了保証は cooperative で、停止遅延を上位へ報告する timeout/分類がない。P0/P1 は今回追加確定なし。

## Findings

### RT-01 — P2候補: server shutdown が全 task の cooperative completion を無期限に待つ

- **該当パス / シンボル**
  - `crates/pumpkin/src/server/mod.rs:442-449` `Server::spawn_task`: `TaskTracker` に task を登録。
  - `crates/pumpkin/src/server/mod.rs:747-751` `Server::shutdown`: `tasks.close()` 後に `tasks.wait().await`、その後に world shutdown/save。
  - `crates/pumpkin/src/lib.rs:528-533` listener-owned client task tracker を close/wait してから `self.server.shutdown()`。
  - `crates/pumpkin/src/plugin/mod.rs:287-376` hot-reload watcher は停止時 `JoinHandle::abort()` を呼ぶが、abort completion/error の観測はない。
- **根拠 / 状態**
  - `Server::spawn_task` の契約コメントは task が「reasonable amount of time」で終了することを呼出し側に要求するが、停止時 deadline、timeout、未完了 task 名の記録はない。
  - server-owned task には telemetry loop、plugin task、chunk/entity cleanup、scheduled task などが含まれる。task 自体が stop signal/finite completionを正しく扱うかは個別実装に依存する。
  - したがって、異常な plugin task または stop signalを待たない task が残ると、world save と `level.dat` final write の前に shutdown が停止する可能性がある。
- **確度**: 中（無期限 wait の構造は確定、実際の停止ハングは未実行）。直ちに server crash と断定しない。
- **症状**: graceful shutdown の完了・world persistence が遅延または未到達になる候補。通常経路では既存の `STOP_INTERRUPT`、client `close_token`、各 `TaskTracker` により完了する可能性がある。
- **最小テスト案**
  1. test-only taskを `Server::spawn_task` に登録し、stop signalを無視したまま shutdown を呼ぶ。
  2. shutdownが無期限に待たず、timeout後に task名/分類をログし、world saveを続行または明示的失敗にする仕様を決める。
  3. normal task、client task、hot-reload watcher、plugin taskの終了順と、world save前後の invariantを記録する。
- **修正案**: task registryに用途/所有者/名前を付与し、shutdown waitに設定可能な deadlineと診断を導入する。plugin/外部IO taskは cancellation tokenを共有し、`abort`後は join結果を観測する。今回は実装しない。

## 既存防御・正常経路

- Java/Bedrock client task自身には client-level `TaskTracker` と `await_tasks()` があり、close後に待機する (`crates/pumpkin/src/net/java/mod.rs:374-376`, `crates/pumpkin/src/net/bedrock/mod.rs:611-614`)。
- listener-owned task trackerは `crates/pumpkin/src/lib.rs:468` で作成され、停止時 `close`/`wait` される (`:528-531`)。
- `Server::shutdown` は task wait 後に各 world `shutdown` を呼ぶため、通常完了時の「taskを止めずに保存」経路は静的には確認しなかった。
- 本補完で client framing/state/network finding、world storage、tick schedulingの他文書findingを重複計上しない。

## Recommended Next Steps

1. timeout仕様を決める前に、task owner/nameを収集する小さな診断テストを追加する。
2. graceful shutdownの正常系を維持したまま、hung plugin/IO taskを別テストで検証する。
3. runtime問題を実装する場合も、network/world/task ownershipごとに分離し、今回の正式コード変更には含めない。
