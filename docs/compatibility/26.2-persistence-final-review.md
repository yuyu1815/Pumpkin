# 26.2 entity persistence final review

- Target: Java Edition `26.2`, protocol `776`, world data version `4903`
- Review base: `802353e33` shutdown stack fix plus the uncommitted persistence patch reviewed in this worktree
- Scope: entity save/load, eviction, autosave, world shutdown, server shutdown, WASM `World::save`, cache/worker ordering, and public callsites
- Decision: **mergeable for the reviewed P1 persistence paths after the follow-up fixes below; not a full vanilla compatibility approval**

## Findings

### P1 findings resolved

1. **Non-resident live entities are no longer treated as already saved.**
   `World::save_entity` calls `Level::save_entity_nbt` for both resident and non-resident chunks. The bounded path loads the existing entity chunk without generation fallback, merges by UUID, marks it dirty, and returns the entity-saver write error to the caller.

2. **Loaded, missing, and error are separated.**
   `LoadedData::Loaded` remains a successful read; `LoadedData::Missing` creates an empty save candidate; `LoadedData::Error` returns an error from the save path and does not generate or overwrite an empty chunk. The normal receive path logs an error and leaves the corrupt/original file untouched.

3. **Eviction and save IO are serialized.**
   `Level::entity_save_lock` covers entity-chunk load/merge/write, normal receive-cache insertion, generation publication protection, eviction map removal, and final shutdown flush. The previous race where `clean_entity_chunks` removed the map entry before waiting for the lock was fixed: removal now occurs under the same lock, and a failed write reinserts the cache entry.

4. **Generation cannot replace a newer save snapshot.**
   `spawn_entity_generation` uses `DashMap::entry(...).or_insert(...)`; an empty generation result no longer replaces a `Missing` chunk published by `save_entity_nbt`. Regression test: `level::tests::generated_missing_chunk_does_not_replace_saved_snapshot`.

5. **Boundary destination follows the serialized position.**
   `World::save_entity` derives the destination chunk from the serialized `Pos` NBT, with a `block_pos` fallback only for malformed/missing position data. This removes the old “old chunk selected, new position serialized” eviction failure mode. A full tick-freeze/versioned entity snapshot is still not implemented; see limits.

6. **Shutdown and write failures propagate.**
   `Level::shutdown`, `World::shutdown`, `Server::shutdown`, `World::save`, and `remove_entities_in_chunks` now return `Result`. `Level::write_entity_chunks` returns serializer errors; `World::shutdown` does not clear entity indexes or finish level teardown before entity/POI/level writes succeed. `World::save` is returned through the WASM host result. `tokio::spawn` `JoinError` from the boxed entity-save task is converted and propagated.

### Lock-order investigation

The reviewed order is:

1. `entity_save_lock`
2. entity saver / file-manager serializer lock
3. file-manager watcher access, after serializer guards are released as required by `ChunkFileManager`

`watch_chunks`/`unwatch_chunks` do not acquire `entity_save_lock`, so there is no reverse `watcher -> entity_save_lock` order. `Level::shutdown` drains task trackers and entity-saver operations before taking the final entity-save lock, then performs the final cache snapshot/write under that lock. No lock cycle was found in the reviewed callers.

### Entity-saver cache/worker investigation

`ChunkFileManager` still provides per-region serializer locks, bounded channels, and cache eviction only after active references are gone. The new Level mutex is deliberately outside that per-file lock and serializes the higher-level load/merge/write transaction. Normal `receive_entity_chunks` now holds the Level mutex across its disk fetch and cache insertion, then releases it before forwarding notifications. This prevents an old fetch result from being inserted after a newer direct save.

The public `get_entity_chunk` path was also placed in the same ordering domain. Generation publication preserves an already-published save candidate.

### Eviction/deletion investigation

- UUID replacement is performed in-place for an existing saved UUID; repeated saves do not append duplicates.
- A removed entity is not saved by `World::save_entity` when its removal flag is set.
- If eviction save fails, the entity is restored to `World::entities` and `EntityTracker`; cleanup is not attempted.
- If chunk cleanup fails after entity save, the chunk remains/re-enters `loaded_entity_chunks` for retry and is not treated as evicted.
- Disconnect, player chunk unload, chunk movement, and autosave callers all stop before `clean_entity_chunks` when `remove_entities_in_chunks` fails; cleanup failures are logged without dropping the retained cache.

## Public/API impact reviewed

The following return types changed and all repository callsites were searched and updated explicitly:

- `Level::{shutdown, clean_entity_chunks, clean_entity_chunk}`
- `World::{shutdown, save, remove_entities_in_chunks}`
- `Server::{shutdown, unload_world, save_all}` callers
- WASM `HostWorld::save` now returns the nested `Result<(), String>` from `World::save`

The save-only test helpers `load_entity_chunk_for_save` and `persist_entity_chunk`, and the internal `write_entity_chunks`, were kept crate/private rather than expanding the external API. No generated data, protocol API, plugin identity, or hook behavior was changed.

## Limits and unverified cases

- No real `World` spawn -> position change across a chunk boundary -> stop -> second process/reopen UUID/type/position/NBT comparison was added in this checkpoint. The fixture is direct storage IO plus generation/cache ordering, not a mock-only claim, but it does not exercise a live concrete entity implementation.
- The position destination is consistent with the NBT snapshot, but `Entity::set_pos` and individual entity fields remain atomics without one global tick/version freeze. Concurrent mutation during `write_nbt` can still produce a mixed-field snapshot; proving or fixing that requires a broader entity snapshot contract.
- Corrupt-file normal entity loading now fails closed and preserves the original file, but policy for operator repair/recovery remains outside this change.
- Vanilla client acceptance, plugin-specific save behavior, and multi-world failure recovery were not claimed.
- The original repository `target/` remains approximately **19G**; the dedicated target is approximately **8.0G**. Source/test commands used only `C:/Temp/pumpkin-target-26_2-next` for this review. The original target was not deleted because it was not created by this review.
- C: free space measured approximately **185.46 GiB**, above the requested 30 GiB threshold.
