# 26.2 reconfiguration egress barrier fix

## Findings

- Target: Java Edition 26.2 / protocol 776.
- Root cause was not a harness timeout. `JavaClient` had separate normal and
  high-priority `mpsc` queues, while all packets were already serialized to
  untagged `Bytes`. The high-priority writer could overtake normal traffic, and
  a packet produced by a world/entity sender after the connection had entered
  Configuration could still carry a Play packet ID while being queued under the
  mutable Configuration state. The harness correctly mapped that first wire
  violation as an unknown Configuration packet (historical IDs: 83, 54, 117).
- The previous `pending_bytes == 0` barrier did not establish a single enqueue
  ordering point and could not identify the protocol state used to encode a raw
  byte buffer. It also dropped some packets during the barrier, risking lost
  world synchronization.

## Changes

### `crates/pumpkin/src/net/java/mod.rs`

- `JavaClient` now has one FIFO outgoing channel and one TCP writer. Normal,
  high-priority, broadcast, keep-alive, movement, chunk, and disconnect sends
  all cross the same queue. Completion is retained for synchronous sends rather
  than using a second priority queue.
- `EgressGate` serializes state capture and transition ordering. Each queued
  packet records:
  - encoded protocol version;
  - encoded connection state and `ConfigurationPhase`;
  - monotonic egress epoch;
  - first packet ID decoded from the serialized buffer;
  - typed-vs-raw origin and Start Configuration marker kind.
- `Play -> Configuration` increments the epoch while holding the gate and
  appends `start_configuration` after already-captured Play packets. New Play
  packets are retained in a deferred queue, not dropped, until the Finish
  acknowledgment returns the connection to Play.
- Configuration phases block Play egress for the complete transition, not only
  the short marker window. Typed Configuration packets remain on the main FIFO;
  raw bytes from world/entity/chunk paths are explicitly captured as Play and
  deferred when the current coarse state is Configuration. This avoids treating
  a bytes-only queue as state-neutral.
- Finish acknowledgment changes the connection to Play under the same gate and
  appends deferred Play packets after all Configuration traffic. The same
  `Arc<Player>`, world, entity, position, and inventory remain in place.
- The sole TCP writer validates the captured state/phase/epoch/version/packet
  boundary before framing. An optional test-only
  `PUMPKIN_JAVA_EGRESS_TRACE_FILE` records enqueue, writer, release, and first
  boundary-violation records; it is unset in normal server operation.
- `crates/pumpkin/src/net/java/config/known_packs.rs` marks serialized
  Configuration registry/tag packets as typed Configuration egress so the
  shared raw-byte API cannot misclassify them.
- `crates/pumpkin/src/net/java/config/config_acknowledged.rs` uses the gated
  Finish-to-Play transition and deferred-queue release.

### `crates/pumpkin/tests/java_reconfiguration_tcp.rs`

- The real TCP test enables the test-only writer trace at
  `C:/Temp/pumpkin-26_2-current-egress.log` and prints the harness/server
  diagnostics on successful normal and EOF probes. It does not relax packet
  expectations or increase timeouts.

### `tools/compat-26_2/protocol776_harness.py`

- The strict first-chunk observer now parses the 1.20.2+ unnamed NBT form used
  by protocol 776 block entities. The old parser treated the first zero-valued
  light-mask byte as a legacy NBT root-name byte, which produced intermittent
  false `trailing bytes` failures when the first chunk contained block entities.
  The fix is a cursor correction, not an opaque-payload relaxation; a regression
  fixture covers an unnamed empty compound immediately before zero light masks.

## Validation boundary

- The strict harness mapping and frame/packet expectations were not loosened.
  The initial chunk failure was a harness NBT cursor bug, not evidence of normal
  packet loss and not converted into a pass by dropping packets.
- Source review found one FIFO `UnboundedSender`, one TCP writer, gate-serialized
  state capture, explicit raw-vs-typed origin, epoch/phase/version/packet-ID
  validation, deferred Play retention, and gate-held Finish-to-Play release.
  Backpressure closes at `MAX_PENDING_BYTES`; close drains deferred packets and
  completes waiters. No blocking await occurs while holding the egress mutex.
- No user `.pi/` state, repository world, or formal server data was touched.
  The integration server uses only a temporary world and loopback port.
- This is a synthetic protocol peer and real Pumpkin in-process TCP evidence,
  not a formal vanilla 26.2 client approval. Registry/chunk/NBT meaning,
  online-mode/encryption, production reconfiguration trigger, and official
  client rendering/acceptance remain unverified.
