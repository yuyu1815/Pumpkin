# 26.2 real World entity persistence E2E

- Target: Java Edition `26.2`, protocol `776`, world data version `4903`
- Scope: concrete `World` entity spawn, live position/custom NBT mutation, chunk-boundary movement, new-spawn persistence, world stop, and independent `World`/`Level` reopen.
- Test symbol: `crates/pumpkin/src/world/mod.rs::tests::world_entity_persistence_e2e_spawn_move_stop_reopen`
- Implementation symbols: `World::{save, shutdown}`, `World::save_entity`, `Level::save_entity_nbt`

## Contract under test

The regression must use the production world/entity path rather than a direct entity-region fixture:

1. Create an isolated temporary world and a concrete `minecraft:armor_stand` through `entity::type::from_type`.
2. Publish it through `World::spawn_entity_non_save` and mutate live `Pos` and `Entity::custom_data`.
3. Save an initial snapshot, move the live entity across a chunk boundary, and save again.
4. Spawn a second concrete entity directly in a non-resident destination chunk without an earlier snapshot.
5. Call `World::save`, then `World::shutdown` (the stop/persistence boundary).
6. Construct an independent `World`/`Level` over the same temporary world and load the actual entity chunks through `Level::receive_entity_chunks`.
7. Compare UUID, entity type, exact `Pos`, and `PumpkinCustomData`; assert the old chunk is empty and the reopened UUID set has no duplicates.

The old-chunk assertion is intentional: a live entity may have been saved before moving. `Level::save_entity_nbt_with_stale_chunk` removes that UUID from other cached entity chunks and from the supplied non-resident previous chunk while publishing the destination snapshot, so a reopen cannot resurrect the old copy.
