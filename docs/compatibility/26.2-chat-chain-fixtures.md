# 26.2 chat 認証: stateful 実装計画と独立 fixture

## Findings

### 調査範囲と HEAD

この調査で正式 Rust code は変更していない。書き込み対象は本ファイルと
`tools/compat-26_2/chat-fixtures/` だけである。作業時の `HEAD` は
`d19ecad2c8463dfed73784a109d4ec9b75b4a70d`（`docs(compat): record 26.2
integration evidence`）で、対象の stateless helper を追加した親は
`427c10a7f`（`feat(chat): add stateless 26.2 signature helper`）である。
`427c10a7f` は canonical bytes と RSA known-answer test までであり、packet
acceptance、chain state、ack commit、signed command には接続していない。

確認した正式コードの境界は次の通り。

- `crates/pumpkin/src/net/chat/signature.rs`
  - `canonical_bytes` は marker/link/body/last-seen の純粋な byte builder。
  - `verify_canonical_signature` は DER SPKI と RSA PKCS#1 v1.5/SHA-256 を検証。
  - `verify_chat_message_signature` は state を変更しない。
- `crates/pumpkin/src/net/java/play/chat_message.rs`
  - `JavaClient::handle_chat_message` は `/` を通常 command に先に分岐する。
  - `validate_chat_message` は secure mode で署名長、時刻、session expiry、offset/ack、pending 数、checksum を見るが、上記 verifier を呼ばない。
  - ack validator は checksum 検査より前に mutate し得る。
- `crates/pumpkin/src/entity/player.rs`
  - `ChatSession` は `messages_sent`/`messages_received` を持つが、inbound chain の next index/last timestamp/broken state は持たない。
  - `LastSeenMessagesValidator::apply_update` は offset 適用後に 20-bit ack を追跡 window に適用する。失敗時の transaction はない。
- `crates/pumpkin/src/net/java/play/chat_ack.rs::JavaClient::handle_chat_ack`
  - offset-only ack を `last_seen_validator` に直接適用する。message signature verification とは別経路である。
- `crates/pumpkin/src/world/mod.rs::World::broadcast_secure_player_chat`
  - inbound message に `messages_sent` と `Uuid::nil()` session を使って broadcast object を作る。これは inbound link の代用にしてはいけない。
- `crates/pumpkin/src/net/java/mod.rs` の `SChatCommandSigned` 分岐
  - signed packet の metadata を検証せず command text に降格し、decode failure 時は通常 command decoder に fallback する。

### 公式 26.2 一次証拠と互換性の主張範囲

静的 oracle は repository 外の公式 JAR
`C:/Temp/minecraft-26_2-server.jar` である。outer JAR は SHA-1
`823e2250d24b3ddac457a60c92a6a941943fcd6a`、size `60,894,273` bytes。
`META-INF/versions/26.2/server-26.2.jar` は size `24,952,681` bytes、SHA-1
`86765a5899bd9c96461036a628796b4245715058`。対象 class/method は
`PlayerChatMessage.updateSignature`、`SignedMessageLink.updateSignature`、
`SignedMessageBody.updateSignature`、`LastSeenMessages.updateSignature`、
`LastSeenMessages.Update`、`SignedMessageChain`、
`LastSeenMessagesValidator`、`RemoteChatSession` である。

この bytecode 静的解析から確認できるのは、次の serialization/比較順序である。

```text
int32_be(1)
sender UUID (16 bytes)
session UUID (16 bytes)
int32_be(link.index)
int64_be(salt)
int64_be(Instant.epochSecond)
int32_be(content UTF-8 byte length)
content UTF-8 bytes
int32_be(last_seen count)
last_seen signatures (each 256 bytes, tracked-window order)
```

`LastSeenMessages.Update` は wire の offset、固定 20-bit ack、checksum を扱い、
ack bit `i` は `ack[i / 8]` の bit `(i % 8)` である。公式 chain の比較は
古い timestamp (`isBefore`) と signature verification failure を成功 commit
前に拒否し、成功した message の後で link/timestamp を進める。これは static
bytecode の照合結果であり、vanilla server/client の実往復や kick 文言を確認
した証拠ではない。

**既存 known-answer の provenance は二層に分ける。** canonical layout、
marker、UUID/link/body/UTF-8/epoch-second の順序は上記公式 26.2 bytecode
由来である。一方、`427c10a7f` に埋め込まれた empty-`last_seen` の値、RSA
public DER、256-byte signature は Mojang が配布した fixture ではない。固定
2048-bit test key で OpenSSL 3.2.2 が repository 外で生成した自己生成の
known-answer であり、private key は保存していない。canonical field 値と
SHA-256 も公式配布値ではなく、この作業で計算した値である。従ってこの
fixture は「公式 layout と独立した RSA verification の一致」を示すだけで、
公式署名鍵、vanilla acceptance、online-mode 相互接続を主張しない。

### stateful 実装で分離する責務

| 責務 | 入力 | accept 時の commit | reject reason（fixture の安定 ID） | 根拠/未確認 |
|---|---|---|---|---|
| message index | current session、expected next index、link index | valid message 後だけ `next_index += 1` | `index_not_next` | chain/link の index advance は公式 bytecode 照合済み。Pumpkin の既存 `messages_sent` は代用不可。 |
| session replacement | validated `SPlayerSession`、old/new session UUID/key | certificate 成功後に new session と新 chain root を atomically install | `invalid_session_certificate` / `session_mismatch` | `validate_chat_session` と `ChatSession::new` は確認済み。ack window を replacement で保持/破棄する exact vanilla sequence は実往復未確認。 |

## Migration / Investigation Notes

### 次の狭い 70-turn 実装（正式 code は別 owner が担当）

1. **Fixture reader/contract（最初の小単位）**: JSON fixture を読む新 framework は
   作らず、既存 unit-test から展開できる固定 schemaとして扱う。まず
   `canonical-empty-last-seen.json` と `last-seen-ack.json` の byte/hash を
   pure helper に接続する。cargo はこの調査では実行しない。
2. **Ack preview（stateful integration 前）**: `LastSeenMessagesValidator` の
   clone/transaction 相当を用意し、`offset + 3-byte ack` から ordered
   acknowledged signatures と checksum を計算する。`checksum=0` は公式の
   bypass case だが署名検証の代替ではない。preview error なら original
   validator/cache を一 byteも変えない。
3. **Chain state**: `ChatSession` または専用の session-owned state に
   `inbound_session_id`、`next_index`、`last_timestamp`、`broken` を持たせる。
   `messages_sent`（outbound broadcast count）/`messages_received`（recipient
   count）を inbound link に流用しない。signature、index、timestamp、ack
   preview が全て成功した後だけ一括 commit する。
4. **Session replacement**: `SPlayerSession` の certificate、expiry、DER key
   を先に検証する。成功した replacement だけ new session root を installし、
   old session の署名を `session_mismatch` とする。ack window を保持するか
   reset する仕様は、公式 class の状態遷移を追加確認するまで fixture の
   `deferred` を変更しない。
5. **Acceptance**: `allow_chat_reports=true` では valid session certificate、
   unexpired session key、256-byte RSA/SHA-256 signature、canonical body、chain
   index/timestamp、ack/checksum を全て要求する。invalid signature/ack/replay の
   後に secure broadcast または state advance をしない。
6. **Signed command は別 owner/task**: `SChatCommandSigned` を
   `handle_chat_command` へ text-only fallback しない。ただし argument signature
   の canonicalization は未確認なので、message canonical bytes を流用せず、
   公式 26.2 class の追加一次証拠が揃うまで execution を `deferred` にする。
7. **Offline/policy**: `allow_chat_reports=false` は unsigned/system chat を
   secure attribution として扱わない合法な設定境界として維持する。`online_mode=false`
   は identity proof ではない。`allow_chat_reports=true` では offline/online を
   問わず secure session が必要で、session 無し/expiry 済み/invalid certificate
   は secure chat acceptance にしない。

### 独立 fixture の構成

fixture は `tools/compat-26_2/chat-fixtures/` に置く。ファイルは実行 harness
ではなく、次 owner が pure unit test に移すための入力/expected contract である。

- `README.md`: schema、provenance、権利/secret 方針。
- `canonical-empty-last-seen.json`: 66-byte canonical known-answer と、既存
  stateless helper の RSA positive/negative provenance。
- `chain-state.json`: index、replay、timestamp、session replacement の分離。
- `last-seen-ack.json`: offset、20-bit bit order、ordered signatures、checksum、
  reject 時の no-mutation 期待値。
- `signed-command.json`: command を message chain と混ぜない入力、secure session
  条件、argument canonicalization 未確定の `deferred` case。
- `policy.json`: reports disabled の unsigned case と secure-session-required
  条件。

### 最小テスト群（次 owner への handoff）

1. `canonical_empty_last_seen_matches_official_layout_hash` — length `66`、canonical
   hex、SHA-256 `6ca6cc185f024bc125cd5beec691bf4541541dfc73c6d8322801276a01387d10`。
2. `independent_rsa_signature_accepts_only_unchanged_payload` — valid、content/salt/
   timestamp/session/index/last-seen mutation、wrong key、zero/255/257-byte signature。
3. `last_seen_ack_preview_preserves_window_order` — `05 00 00` が slot 0,2 を
   `[sig-A, sig-C]` の順で返す。
4. `last_seen_offset_is_applied_before_bitset` — offset `2` 後の slot 0 を対象にする。
5. `last_seen_reject_does_not_commit` — unknown/repeated/checksum mismatch で state
   snapshot が同一。
6. `chain_accept_commits_once` — index 0 then 1 の valid sequenceだけ advance。
7. `chain_replay_and_old_timestamp_reject_without_advance` — `index_not_next` と
   `out_of_order_timestamp` を別 assertion にする。
8. `session_replacement_rebinds_signature_session` — valid replacement 後の old
   session reject。ack window policy は deferred assertion のままにする。
9. `secure_policy_requires_session_but_reports_disabled_allows_unsigned` — policy
   fixture の二経路を混ぜない。
10. signed command は今は parser boundary と `no_fallback` の contract だけ。argument
    signature acceptance test は official canonicalization evidence 後に追加する。

## 権利・秘密情報の扱い

公式 JAR は一次実装の静的 oracle として repository 外の
`C:/Temp/minecraft-26_2-server.jar` を参照しただけで、repository にコピー/再配布
しない。Mojang EULA と repository の GPL-3.0/`assets/NOTICE.md` の attribution 境界を
維持する。Paper/MCProtocolLib の補助照合結果をコードとしてコピーしない。

fixture に含める RSA public DER と signature は test-only の自己生成値であり、
Mojang key、公式署名、実ユーザー token、session private key ではない。private key は
生成元にも repository にも残さない。JAR、private key、token、packet capture、world
artifact は `chat-fixtures/` に入れない。
