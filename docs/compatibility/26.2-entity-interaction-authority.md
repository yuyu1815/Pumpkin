# 26.2 entity attack/interact reach authority 仕様照合・最小修正

- 対象: Java Edition 26.2 / protocol `776` / world data version `4903`
- 対象経路: `crates/pumpkin/src/net/java/play/attack.rs`、`interact.rs`
- 変更境界: `entity/player.rs`、`world/mod.rs`、attribute本体はread-only。root manifest、generated data、`.pi/`、stage/commitは変更していない。
- 実装方針: 公式26.2 server JARのpacket handlerとrange計算を基準に、attack/interactの副作用（plugin event、damage、item interaction）より前に確実なauthority guardだけを追加した。

## Findings

### 公式26.2で確認した仕様

公式JAR `C:/Temp/minecraft-26_2-server.jar` の内包 `META-INF/versions/26.2/server-26.2.jar` を `C:/Temp/server-26.2.jar` として確認した。`javap -c -p` の主要結果:

- `net.minecraft.server.network.ServerGamePacketListenerImpl.handleAttack`
  - `hasClientLoaded()` と攻撃者 `isSpectator()` を確認。
  - targetを**同じServerLevel**から解決し、world border内であることを確認。
  - targetのAABBに対して `ServerPlayer.isWithinAttackRange(item, AABB, 3.0D)` を確認。
  - itemのattack range componentが無効/未対応、item feature無効、自己/ItemEntity/ExperienceOrb/attackableでない矢などは拒否またはinvalid entity扱い。
  - その後にだけ `ServerPlayer.attack(target)`。
- `handleInteract`
  - `hasClientLoaded()`、同じServerLevelからのtarget解決、world border、`isWithinEntityInteractionRange(AABB, 3.0D)` を確認。
  - 公式handlerにはblock line-of-sight/raycast guardはない。したがって「壁越しは必ず拒否」は26.2 packet-handler仕様ではなく、今回追加していない。
  - `ServerPlayer.isWithinEntityInteractionRange` は eye positionからtarget AABBへの最短距離を使い、`entityInteractionRange + 3.0` の**strict `<`**。
- `net.minecraft.world.entity.player.Player`
  - `entityInteractionRange()` は `ENTITY_INTERACTION_RANGE` attributeのeffective value。
  - `isWithinEntityInteractionRange(AABB, 3.0)` は target AABBへの最短距離二乗 `< (attribute + 3.0)^2`。
  - `AttackRange.defaultFor(LivingEntity)` は `ENTITY_INTERACTION_RANGE`をmax reachに使う。
- `net.minecraft.world.item.component.AttackRange`
  - item componentがある場合、survival/creative別のmin/max reach、hitbox marginを使用。
  - 判定は距離 `>= min - margin - 3.0` かつ `<= max + margin + 3.0` のinclusive境界。
  - 26.2 vanillaはmob factorをmob attacker用に使うが、今回のcallerはPlayerなので適用しない。
- `net.minecraft.server.level.ServerPlayer.updatePlayerAttributes`
  - creative時、`ENTITY_INTERACTION_RANGE`にtransient `+2.0` (`creative_mode_entity_range`) を加える。
  - したがって通常playerのdefault entity range 3.0はcreativeで5.0となり、handlerのverification buffer込みの上限は8.0相当。block rangeの`+0.5`はentity判定に混ぜない。

### 現行コードの反証・不足

- `attack.rs:5-58` と `interact.rs:6-133` の旧経路には、target id解決後の距離、target world、removed/dead living、spectator、AABB最近点判定がなく、event/damage/item interactionへ進み得た。
- `Entity::has_line_of_sight` (`crates/pumpkin/src/entity/mod.rs:3447`付近) は存在するが、公式26.2の攻撃/interaction packet handlerはこのguardを呼ばない。AI/projectileのLOS利用をplayer packetの仕様根拠に拡張しない。
- `EntityBase::can_hit` はmob/boat/minecart/interactionなどのattackable entityには有用だが、Playerは既定値falseであるため、Playerだけを`can_hit()`単独で拒否するのはfalse positive。実装はliving entityまたは`can_hit()`をattack targetとして許可する。
- current world lookupは通常同じworldを返すが、target Arcのworld ownershipを明示的に比較し、removed targetとdead living targetを副作用前に拒否する。

### 確度

- 公式JARのbytecodeと現Rustの静的data-flowは高確度で照合済み。特にrange buffer `3.0`、creative entity bonus `+2.0`、AABB最近点、attack inclusive / interact strict boundary、LOS非必須は直接根拠がある。
- Pumpkin handlerの実client挙動、world borderの実fixture、plugin event counter、custom entityの実wire挙動は未実行。したがって「修正がcompile/test済み」「vanilla clientで受理済み」とは扱わない。

## Migration / Investigation Notes

### 変更内容

1. `attack.rs` に共通validatorを追加。
   - target worldは`Arc::ptr_eq`でattacker worldと一致することを確認。
   - target removed、spectator、living health `<= 0.0`を拒否。
   - attackではspectator attackerと、livingでも`can_hit`でもないtargetを拒否。
   - eye positionからtarget bounding box最近点までの距離を使用。
   - attackはitem `AttackRangeImpl`のsurvival/creative rangeとhitbox marginを尊重。componentなしはentity interaction attributeを使用。
   - creative entity range `+2.0`、vanilla verification buffer `+3.0`を適用。
   - non-finite distance/range/bounding boxは拒否。
2. `interact.rs` で、target解決後かつplugin event前に共通validatorを呼ぶ。target不在時も`PlayerInteractUnknownEntityEvent`を発火せず、attackだけ従来どおりinvalid entityとしてkickする。
3. world borderは`Worldborder::contains_block`でauthority guardに含めた。壁越しLOS/raycast、sweep AABB、movement authority、dimension lifecycleは公式packet handlerの必須条件として確認できないため別policyのままとした。公式handlerの範囲判定を越えて仮説を仕様化しないためである。
4. 既存のspectator camera経路は、同じworld・距離guardを通った後に実行される。dead/spectator targetはattack-only guardから分離し、通常のattackはspectator attackerを拒否する。Ender Dragon partは`World::get_entity_by_id`で本体のpart indexから解決する。PiercingWeaponは通常の`Player::attack`経路を拒否する。item feature/cannot-attack-with-itemは現Rust item modelの表現不足により未解消である。
