# 26.1 基盤のための条件付き許容リスト（最終対象 26.2）

## Findings

この文書の「許容」は、26.1 を比較・replay・fixture の基盤にしたとき、**差分自体は 26.2 の仕様差として説明できるが、意味・参照整合性・順序・数量を壊していないことを条件に通過させられる範囲**を指す。26.2 server/client の完全互換を宣言するものではない。

- 最終対象: Java Edition `26.2`、protocol `776`、world data `4903`。
- 比較元: Java Edition `26.1`、protocol `775`。26.1 は比較専用であり downgrade target ではない。
- status の意味:
  - `verified`: 一次資料と repo asset の限定比較で、差分の形と局所的な変換契約を確認済み。ただし vanilla client 実行を意味しない。
  - `proposed`: 根拠はあるが、実 client/server、全 payload、または round-trip が未検証。有効 allowlist へ昇格させない。
  - `blocked`: version差として扱うことを禁止。候補/要調査として記録するだけ。
- **今回の最終有効ruleは `verified` 0件**（`enabled: true` も0件）。`proposed`/`blocked` は承認済み allowlist ではない。ID 62を含む名前差は source系不一致のため、実version差として確定せず有効化しない。

### 条件付き候補（未承認。allowlistへ有効追加しない）

#### `ALW-2601-WORLD-PATH-MIGRATION` — `proposed`

- **from/to:** 26.1 world layout → 26.2 canonical layout、対象は `dimensions/minecraft/overworld`、`DIM-1`/`DIM1`、root `data`、`players/`、`resourcepacks/`、`generated/.../structures` 等。
- **根拠:** official 26.1 release notes の World Storage は dimensions/player/data namespace 化と rename を明記。`crates/pumpkin-world/src/level.rs` と `world_info/data_files.rs` は 26.x canonical/legacy layout を読む経路を持つ。26.2 current world data は `4903`、level version `19133` を保護する。
- **期待する変換:** path alias は既知 path の読み出し・明示的な 26.2 path への保存に限る。`level.dat`/region/entity/poi/data の参照を保ったまま、DataVersion/level version を検査し、成功時のみ 26.2 値へ stamp する。seed、tick、scheduled events、block entities、components、UUID、registry references、directory ordering を削除/再番号化しない。
- **検証:** 26.1 実 world fixture を repo 外で読み、26.2 pathへ書き、再読込して NBT semantic diff、region/chunk、entity/poi、registry/tag、seed/tick/componentを比較。その後 vanilla 26.2 server/client の acceptance を別証拠にする。
- **未承認理由:** 26.1 JAR/world と end-to-end upgrade の実測が無い。現行 source audit/fixture は部分確認であり、migration pass を宣言できない。
- **許容しない例:** path が読めたことだけで conversion pass、`DataVersion=4903` の version文字列だけで pass、未認識 NBTを捨てる、chunk/registry/tag/seed/tickを省略、references/orderを変更する。

#### `ALW-2601-DATA-ID-REMAP` — `blocked`

- **from/to:** 26.1 numeric IDs → 26.2 numeric IDs。対象は item/blockstate/entity/data component IDs。
- **確認済み差:** Via `mapping-26.2to26.1.json`（Mappings commit `492b75b73a82a9b7c55d247de636da22a83e111e`）は blockstates `28`、items `31`、entities `1`、data_component_type `1` の diff を持つ。repo asset の共通名 ID は item `1480/1506`、block `170/1168`、entity `27/157`、component `32/110` が変わる。
- **分類:** これは wire replay の ID normalization/translation であり、version差による「無視してよい値」ではない。`assets/viabackwards/data/mappings-26.2to26.1.nbt` や Via mappingを専用変換層で利用する余地はあるが、production 26.2 allowlist にはしない。
- **検証:** mappingの全参照を変換し、item/block/entity/componentの key↔ID round-trip、registry references、tag values、recipe result、entity metadata、chunk palette、component payloadを比較。欠損・duplicate・順序変更を0件にする。
- **許容しない例:** ID mismatch を unknown として skip、registryを空にする、tag/recipe/chunk paletteの参照を部分変換、数量や component payloadを落とす。

#### `ALW-2601-REGISTRY-SCHEMA-DELTA` — `blocked`

- **from/to:** Data Pack `101.1` / 26.1 registry/data → Data Pack `107.1` / 26.2 registry/data。
- **確認済み差:** 26.2 release notes の `minecraft:sulfur_cube_archetype` registry、`minecraft:sulfur_cube_content` component、new attributes/damage/entity data。local datapack全JSON `1,140→7,664`、tags `758→796`、worldgen `65→1,032`。現行 Pumpkin `SYNCED_REGISTRIES` は 26.2 `29` registry、source/generated entry 合計 `397`（chat raw injectionを含む）だが、vanilla client semantic acceptance は未確認。
- **分類:** 追加 registry/data が 26.2 として正しい可能性は高いが、「26.1基盤との差だから registryを全部 skip」は許容できない。
- **検証:** Known Packs tuple、Registry Dataのregistry key/entry key/NBT tag type/value、Update Tagsのcategory/name/ID配列、順序、duplicate、trailing bytesを official 26.2 client/server trace と3-way比較する。
- **許容しない例:** unknown registryを全 skip、registry entryを空で返す、tag valuesを全削除、Known Packs replyだけでpass、registry名一致だけでNBT valueを検査しない。

#### `ALW-2601-ITEM-COMPONENT-RECIPE` — `blocked`

- **from/to:** 26.1 item/recipe representation → 26.2 component-bearing ItemStack/recipe。
- **確認済み差:** component count `110→111`、`minecraft:sulfur_cube_content` 追加。26.2 source recipeには result componentを持つもの `17`、special/unsupported分類 `23`（既存 registry audit）で、codegen/runtimeには component value loss の未確認箇所がある。
- **分類:** components、recipe result、ingredient消費、数量は仕様差として無視できない。componentを空/未設定にすることは version allow ではなく data loss候補。
- **検証:** suspicious stew、transmute、firework/potion/book/map/crossbow/bundle等の item stackを source→generated→protocol serializer→decode→encode で比較し、recipe result count、component map、ingredient/output conservation、recipe book packetを確認する。
- **許容しない例:** countを1に固定、componentを一律削除、recipe resultを `id/count`だけに縮約、ingredient消費/出力/permissionを version差として pass。

#### `ALW-2601-STATEFUL-SEMANTICS` — `blocked`

- **from/to:** 26.1 replay/trace → 26.2 runtime state。対象は quantity、permission、save/load、chat signing、sequence、tick、entity lifecycle、world transition。
- **分類:** protocol ID/name差ではない。version string、`protocol=776`、`DataVersion=4903`、`known_pack_reply=true`、`play_frame_observed` のいずれも、server decisionや永続化の正しさの証明ではない。
- **検証:** 26.2 validation contractの `INV-01`、`BLK-01`、`PLY-ATTACK-INTERACT` を vanilla 26.2 oracleと同じ初期状態で比較し、packet列、decision、inventory/world/entity final state、署名/sequence/tickを同時に記録する。
- **許容しない例:** 数量増減、権限なし操作、保存されない変更、署名 invalid、state transition不整合、参照切れ、順序入替を「26.1と26.2の差」として合格にする。

## Migration / Investigation Notes

### runtime rule format（機械可読ルールとの統合済み）

有効な文書allowlistの機械可読projectionは `tools/compat-data/allowlist-rules.json` に固定する。`manifest.json` の `allowlist_path` がこのファイルを指し、`compat_data.py verify` が重複ID、wildcard、invalid schema、未指定のfrom/to、packet/state/direction不足を拒否する。`verified` かつ `enabled: true` の rule だけが classifier の `allowed_version_delta` になり、`proposed` は `needs_review`、`blocked`・未知rule・契約不備は `fail` であり、自己申告の `allow: true` は無視する。

各 rule は少なくとも次のフィールドを持つ。

```text
rule_id: stable string
status: verified | proposed | blocked
from: {minecraft_version, protocol}
to: {minecraft_version, protocol}
state: handshake | status | login | configuration | play | world | data
 direction: serverbound | clientbound | storage | replay-normalizer
subject: concrete path / packet / field / registry / component
preconditions: explicit version, state, direction, source/provenance, permission/fixture conditions
reason: why this is a version-shaped difference rather than a bug
expected: exact transform/value/preservation rule
verification: command/fixture/oracle and pass/fail invariant
source: URL + retrieval date + local path + commit/hash
reject_examples: concrete cases that must fail or remain unapproved
```

`allow=true` は fixture 自身が自己承認してはならない。`tools/compat-data/fixtures/trace-contract.json` の `allow is computed by compat_data.py`、`observed=false` は synthetic contract であり実 client traceではない、という契約を維持する。`proposed`/`blocked` は runtime allowlistへ取り込まない。現在の有効ruleは **0件**。`ALW-2601-REPLAY-PACKET-LABEL-62` は `proposed/disabled` で、pinned Prismarine schemaの `spectate_entity` と Pumpkin local assets双方の `spectator_action` を版差と断定しない。将来 rule を昇格する場合は `comparison_metadata` の明示契約に加え、`before_metadata` / `after_metadata` の packet_id、opaque payload識別子、順序、field数、数量、packet presence の差分照合を要求する。なお classifier は申告済み差分のポリシー判定器であり、独立した wire/trace検証器ではない。packet追加・削除、順序差、数量改変、payload/schema差は通さない。

最短確認コマンド（リポジトリルート）:

```text
py -3.11 tools/compat-data/compat_data.py fetch
py -3.11 tools/compat-data/compat_data.py verify
py -3.11 -m unittest discover -s tools/compat-data -p "test_*.py" -v
printf '%s\n' '{"source":{"minecraft_version":"26.1","protocol":775},"target":{"minecraft_version":"26.2","protocol":776},"state":"play","direction":"serverbound","classification":"allowed_version_delta","rule_id":"ALW-2601-REPLAY-PACKET-LABEL-62","context":"replay-normalizer","comparison_scope":"comparison_metadata","field":"packet_name","packet_id":62,"packet_name_from":"spectate_entity","packet_name_to":"spectator_action","payload":"unchanged","packet_order":"unchanged","field_count":"unchanged","quantity":"unchanged","packet_presence":"unchanged","preserved":["packet_id","payload","packet_order","field_count","quantity","packet_presence"]}' | py -3.11 tools/compat-data/compat_data.py classify
```

上記classifyは現状 `proposed/disabled` のため `allow=false` / `disposition=needs_review` となる。将来の verified rule でも、metadata差分の policy 判定に過ぎず、26.2 server受理、vanilla client、wire payload意味、gameplay結果を証明しない。`fetch` は manifest の全 pinned URLをcommit/hash検証して ignored `.cache/` に保存する。network失敗はsynthetic testの成功とは別に報告する。

### 実行した確認

- official 26.1/26.2 metadata、release notes、ViaVersion version source、Via Mappings diff、local packet/assets/datapack/tracked dataを比較した。主要 hash/URL/取得日と範囲は `26.1-to-26.2-deltas.md` に固定。
- 26.1 packet asset vs 26.2 packet asset: state/direction/ID comparator。通常 packet ID change `0`、local name changes `6`件、ID `62` は両local assetで `minecraft:spectator_action`。26.1 legacy handshake ID `254` は Prismarine schema側の別 entry。
- Via diff: blockstates `28`、items `31`、entities `1`、data_component_type `1`。
- source-only inventory/world/registry audit: `cargo`、server、vanilla client、packet capture/replayは本担当では実行していない。
- 書込み確認は本ファイルと `26.1-to-26.2-deltas.md` のみ。正式 `src`、assets、tools実装は変更していない。

## Recommended Next Steps

1. `ALW-2601-REPLAY-HANDSHAKE-LEGACY-254` と `ALW-2601-REPLAY-PACKET-LABEL-62` を production decoder の許可規則へ直接変換せず、replay/fixture adapter の分類規則として担当1と統合する。
2. `ALW-2601-WORLD-PATH-MIGRATION` は 26.1実 world fixture、NBT semantic diff、再起動後保存、vanilla 26.2 acceptance が揃うまで `proposed` のままにする。
3. Registry/Tags/Components/Recipes は R3/R1/R4 の既存監査課題を先に検証し、証拠不足の項目を allowlist に追加しない。
4. ID normalization は version allowlistではなく専用変換層・参照整合性テストとして扱う。seed/tick/component、count、権限、署名、state transition、packet orderを一律削除しない。
5. 26.2 の final pass は version文字列だけでなく、protocol/state/field、registry/tag, item component/recipe, world storage、数量・権限・保存・署名・状態遷移を個別に報告する。
