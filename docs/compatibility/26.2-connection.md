# Minecraft Java 26.2 connection 監査・修正記録

- 実施日時: 2026-09-19T01:12--01:23 JST 頃
- HEAD: `1ac447f2918b7dec7d19a5836fa3673d4fe3c9f5`
- 対象: Java Edition 26.2 / protocol `776`
- 所有書込み: `crates/pumpkin-protocol/src/java/**`、`crates/pumpkin/src/net/java/**`、本書
- 判定: 接続の主要 state/packet の確実な 26.2 wire 不整合を 1 件修正。status、handshake、offline login、configuration acknowledgment、known packs、Join Game、keep-alive の packet ID/field/order は、今回確認できた範囲では既存実装を維持できる。実 vanilla client 接続は未実施。

## Findings

### 1. 確実に修正した不整合: 圧縮 threshold 境界

`crates/pumpkin-protocol/src/java/packet_decoder.rs` の `TCPNetworkDecoder::get_raw_packet` は、compression enabled 後の raw packet を `raw_packet_length > threshold` のときだけ拒否していた。Java protocol の compressed format は、packet data length が threshold **未満**のときだけ `Data Length=0` の raw packetを許す。従って length が threshold と等しい raw packet も zlib 圧縮が必要であり、旧条件は境界で不正 packet を受理していた。

修正:

```rust
if raw_packet_length >= threshold as u64 {
    Err(PacketDecodeError::NotCompressed)?;
}
```

回帰テスト:

- symbol: `java::packet_decoder::tests::reject_uncompressed_packet_at_compression_threshold`
- packet id `2` + payload 4 bytes = packet data length `5`
- compression threshold `5`
- `Data Length=0` の raw frame を `PacketDecodeError::NotCompressed` として拒否することを確認

### 2. status / handshake

`assets/packet/26_2_packets.json` と `crates/pumpkin-data/src/generated/packet.rs` の既存 mapping を再利用した。確認した protocol 776 の ID は次の通り。

- handshake serverbound `minecraft:intention=0`
- status serverbound `status_request=0`, `ping_request=1`
- status clientbound `status_response=0`, `pong_response=1`

関連 symbol:

- `crates/pumpkin-protocol/src/java/server/handshake/mod.rs::SHandShake`
  - protocol version は VarInt、server address は bounded String、port は big-endian `u16`、next state は VarInt。
  - address 上限は `i16::MAX` bytes/characters 相当で、forwarding address を許容しつつ過大入力を拒否する既存テストがある。
- `crates/pumpkin/src/net/java/pending.rs::handle_handshake_packet`
  - handshake packet id `0` を decode し、`Status`/`Login` stateへ routing。
- `crates/pumpkin/src/net/java/status.rs`
  - status response の後に ping payload をそのまま pong し、connection を close。

status の実 server smoke は今回再実行していない。既存 harness の synthetic result は `docs/compatibility/26.2-validation.md` に記録された前回成果として扱い、今回の実 server 成功とは合算していない。

### 3. offline login / compression / Login Success

確認した ID:

- login serverbound `hello=0`, `login_acknowledged=3`
- login clientbound `hello=1`, `login_finished=2`, `login_compression=3`

関連 symbol:

- `crates/pumpkin-protocol/src/java/server/login/login_start.rs::SLoginStart`
  - name の上限は 16、26.2 では client UUID を UUID wire type で読む。
- `crates/pumpkin/src/net/java/login/login_start.rs::PendingConnection::handle_login_start`
  - offline mode では `OfflinePlayer:<name>` の UUID v3 を選び、configured compression が有効なら `enable_compression` を呼ぶ。
- `crates/pumpkin/src/net/java/login/encryption_response.rs::PendingConnection::enable_compression`
  - `login_compression` を先に送信し、その後 encoder/decoder に同じ threshold を設定する。Set Compression 自体は compression enabled 前の frame で送られる。
- `crates/pumpkin-protocol/src/java/client/login/login_success.rs::CLoginSuccess`
  - protocol 26.2 では UUID/name/properties の Game Profile に続けて session UUID を書く。`LOGIN_FINISHED=2` を使用する。

圧縮の wire semantics は今回の実修正対象。encoder の `data_len >= threshold` は protocol と一致しており、decoder の境界条件だけを修正した。negative threshold を送る実装は server config の対象外で、推測実装は追加していない。

### 4. configuration / known packs / acknowledgment / packet order

protocol 776 の確認 ID:

- configuration clientbound:
  - `update_enabled_features=12`
  - `registry_data=7`
  - `update_tags=13`
  - `finish_configuration=3`
  - `keep_alive=4`
  - `select_known_packs=14`
- configuration serverbound:
  - `client_information=0`
  - `select_known_packs=7`
  - `finish_configuration=3`
  - `keep_alive=4`
- play serverbound `configuration_acknowledged=16`

既存の state order は次の通りで、26.2 の packet ID と一致する。

1. Login Success (`login_finished=2`)
2. client の Login Acknowledged (`login_acknowledged=3`)
3. server が Configuration state に変更し、branding/link/resource-pack 等を送信
4. server が `update_enabled_features` と `select_known_packs` を送信
5. client が `select_known_packs=7` を返すまで server は待機
6. server が `registry_data`、`update_tags`、`finish_configuration` を送信
7. client が `finish_configuration=3` を返す
8. server が Play state に変更し、`ReadyToPlay` を返す

関連 symbol:

- `crates/pumpkin/src/net/java/login/login_acknowledged.rs::handle_login_acknowledged`
  - Login から Config への切替と `send_known_packs` の入口。
- `crates/pumpkin/src/net/java/login/login_acknowledged.rs::send_known_packs`
  - enabled features → known packs の順に送る。
- `crates/pumpkin/src/net/java/pending.rs::handle_config_packet`
  - `SKnownPacks::to_id(version)` を受信してから registry/tags/finish を送る handler に進む。
  - `SAcknowledgeFinishConfig::to_id(version)` (`finish_configuration=3`) で Config → Play を確定する。
- `crates/pumpkin/src/net/java/login/known_packs.rs::handle_known_packs`
  - registry data → update tags → finish configuration の順。
- `crates/pumpkin-protocol/src/java/client/config/known_packs.rs::CKnownPacks` と `server/config/known_packs.rs::SKnownPacks`
  - 各 entry は namespace、id、version の三つの String。

known-packs client reply の body は現状、server の registry data 省略判定には使用せず、全 registry entry data を送っている。この挙動は wire order を壊さず、protocol 上も許容されるため、client reply の subset 判定を推測で追加しなかった。serverbound packet の受信自体は packet id で待機している。malformed payload の厳密な protocol validation は別残課題であり、今回の互換修正には含めていない。

### 5. Join Game / keep-alive

Join Game の protocol 776 ID は clientbound play `login=49`。`crates/pumpkin-protocol/src/java/client/play/login.rs::CLogin::write_packet_data` の 26.2 suffix は次の順で既存一次表と整合する。

- dimension type VarInt
- dimension name Identifier
- hashed seed Long
- game mode Unsigned Byte
- previous game mode Byte
- debug / flat Boolean
- death location optional
- portal cooldown VarInt
- sea level VarInt
- online mode Boolean
- enforce secure chat Boolean

`CLogin` の 26.2 固有 fields は `online_mode` と `enforce_secure_chat` であり、既存 call site の constructor もこの順に値を渡す。Join Game を別 packet や旧 26.1 schema に置換する修正根拠は見つからなかった。

keep-alive の protocol 776 ID/codec:

- configuration clientbound/serverbound `4`, payload Long
- play clientbound `44`, serverbound `28`, payload Long

関連 symbol:

- `crates/pumpkin-protocol/src/java/client/config/keep_alive.rs` / `server/config/keep_alive.rs`
- `crates/pumpkin-protocol/src/java/client/play/keep_alive.rs` / `server/play/keep_alive.rs`
- `crates/pumpkin/src/net/java/config/keep_alive.rs`
- `crates/pumpkin/src/net/java/play/keep_alive.rs`
- `crates/pumpkin/src/net/java/mod.rs::progress_player_packets`

26.2 の Long は big-endian i64 として encode/decode される。pending ID の照合、重複/未知 ID の無視、config/play state の routing は既存実装を維持した。keep-alive timer は既存 config の値を使用し、今回の packet wire mismatch 修正は不要だった。
