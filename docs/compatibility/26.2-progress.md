## Findings

### 今回確認できた達成事項

1. **Protocol decoder の compression threshold 境界**
   - `crates/pumpkin-protocol/src/java/packet_decoder.rs`
   - `TCPNetworkDecoder::get_raw_packet` の未圧縮判定を `raw_packet_length > threshold` から `>=` に変更。
   - protocol の圧縮仕様上、packet data 長が threshold と等しい場合も compression 必須であることを、`java::packet_decoder::tests::reject_uncompressed_packet_at_compression_threshold` で固定。

2. **Anvil level.dat 保存**
   - `crates/pumpkin-world/src/world_info/anvil.rs`
   - `AnvilLevelInfo::write_world_info` に `create_dir_all(level_folder)` を追加し、新規 world で親ディレクトリがない場合の初回保存を可能にした。
   - `replace_level_dat` を追加し、Windows で既存 destination への rename が `AlreadyExists` になる場合は destination を削除して再 rename。その他の I/O error は握りつぶさず返す。
   - `world_info::anvil::test::rewrite_level_dat_replaces_existing_destination` で `level.dat_new` の残留なしと DataVersion `4903` の再読込みを確認。

3. **main/off-hand swap の inventory 同期**
   - `crates/pumpkin/src/entity/player.rs::Player::swap_item`
   - 選択 hotbar slot (`0..=8`) と off-hand slot (`40`) を `CSetPlayerInventory` で明示送信し、既存の equipment broadcast と `sync_inventory_to_client` を維持。
   - `hand_swap_inventory_slots`、`entity::player::tests::hand_swap_sync_covers_selected_and_off_hand_slots`、`entity::player::tests::player_inventory_swap_changes_the_two_synced_slots` を追加。
   - 現テストは slot mapping と server-side inventory の交換結果を確認する。実 Java client の UI 表示、packet受理、再接続後保存までは確認していない。

4. **strict-play harness**
   - `tools/compat-26_2/protocol776_harness.py` に `--strict-play` を追加。
   - status/login/configuration の state 遷移、Known Packs 応答、Join Game の全 envelope、Player Position と teleport confirmation、first chunk の外側構造、Keep Alive echo を同一接続で検査。
   - `assets/packet/26_2_packets.json` を runtime source として critical mapping を照合し、packet ID の新規推測はしていない。
   - `tools/compat-26_2/test_protocol776_harness.py` は 13 tests。negative test を含め全件成功。

### 互換性として主張してはいけない事項

- **vanilla 26.2 公式 client の接続は未検証。** strict harness は Minecraft client ではなく、opaque payload を含む synthetic TCP peer。
- **全 gameplay 完全互換は未達。** block place、GUI inventory click、通常移動の長時間 trace、追加 chunk の意味論、respawn、chat signing/rendering、resource pack、online-mode/encryption、Bedrock bridge 等は未検証。
- Known Packs には空リストを返しており、registry の同一性を確認した証拠ではない。
- chunk は first chunk の座標、heightmap key/長さ、section-data length、block entity count、light array の境界を検査しただけで、palette、block state、biome、light の意味論や client-side acceptance は未検証。
- strict の `teleport_confirms_sent=[1]` は server に Accept Teleportation を送った事実であり、vanilla client が画面上で受理した証明ではない。
