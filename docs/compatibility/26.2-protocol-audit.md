# Minecraft Java 26.2 protocol schema audit

## Findings

### 1. 版情報の一次証拠

26.2 の版情報は、初期調査の `protocol=776` / `world data=4903` と一致した。

| 項目 | 確認値 | 根拠・確認結果 |
|---|---:|---|
| Java protocol version | `776` | 公式 server JAR の `version.json` の `protocol_version: 776`。ViaVersion `ProtocolVersion.java` の `v26_2 = register(776, "26.2")`（raw source line 97）とも一致 |
| world/data version | `4903` | 公式 server JAR の `version.json` の `world_version: 4903`。Minecraft Wiki の 26.2 ページにも `4903` と掲載 |
| release | `26.2` | 公式 manifest entry: `type=release`, `releaseTime=2026-06-16T12:03:33+00:00`, manifest SHA-1 `987b91a95ae93b3bb78cc14d6e0bbd31bad08d59` |
| official server artifact | 60,894,273 bytes | `https://piston-data.mojang.com/v1/objects/823e2250d24b3ddac457a60c92a6a941943fcd6a/server.jar`, SHA-1 `823e2250d24b3ddac457a60c92a6a941943fcd6a` |
| JAR build metadata | `2026-06-16T12:01:27+00:00`, Java 25 | 公式 server JAR 内 `version.json` |

公式 metadata/JAR はリポジトリへ追加していない。JAR は `/tmp/pumpkin-compat-26_2-server.jar` に一時取得し、`version.json` を抽出して SHA-1 を確認後、外部一時ファイルを削除した。JAR 本体・公式 assets の再配布は行わない。

### 2. `assets/packet/26_2_packets.json` の state/direction/ID 監査

入力 JSON は `phase -> direction -> packet name -> { protocol_id }` の形で、26.2 の 9 state/direction 組み合わせ、合計 256 packet entries を含む。各組み合わせの ID は重複なし、`0..max` の連番で欠落なしだった。

| state | direction | packet 数 | ID 範囲 | 判定 |
|---|---|---:|---:|---|
| handshake | serverbound | 1 | `0..0` | OK |
| status | serverbound | 2 | `0..1` | OK |
| status | clientbound | 2 | `0..1` | OK |
| login | serverbound | 5 | `0..4` | OK |
| login | clientbound | 6 | `0..5` | OK |
| configuration | serverbound | 10 | `0..9` | OK |
| configuration | clientbound | 20 | `0..19` | OK |
| play | serverbound | 69 | `0..68` | OK |
| play | clientbound | 141 | `0..140` | OK |

接続の縦断で重要な ID の抜粋は次の通り。ID の変更や推測補正は行っていない。

- handshake/serverbound: `intention=0`
- status: `status_request=0`, `ping_request=1`; `status_response=0`, `pong_response=1`
- login: serverbound `hello=0`, `key=1`, `login_acknowledged=3`; clientbound `login_disconnect=0`, `hello=1`, `login_finished=2`, `login_compression=3`
- configuration: clientbound `disconnect=2`, `finish_configuration=3`, `registry_data=7`, `select_known_packs=14`; serverbound `client_information=0`, `finish_configuration=3`, `select_known_packs=7`
- play: serverbound `configuration_acknowledged=16`, `keep_alive=28`, `move_player_pos=30`, `move_player_pos_rot=31`, `move_player_rot=32`; clientbound `login=49`, `level_chunk_with_light=45`, `player_position=72`, `update_attributes=131`, `waypoint=138`

26.1 との差分は、名称変更を含むが ID の推測変更ではない。確認できた名称差分は login clientbound の `game_profile` 消失、play serverbound の `command_suggestions -> command_suggestion` / `spectate_entity -> teleport_to_entity`、play clientbound の `chat -> player_chat`、`move_player_rot -> player_rotation`、`set_carried_item -> set_held_slot` である。生成器の既存 alias（例: `GAME_PROFILE -> LOGIN_FINISHED`、`CHAT_MESSAGE -> CHAT`、`HELD_ITEM_CHANGE -> SET_HELD_SLOT`）は旧 API 名の互換用途であり、wire ID の代替根拠ではない。

### 3. 生成物との突合

`crates/pumpkin-data/src/generated/packet.rs` の各 state/direction module にある 26.2 値を入力 JSON と突合した結果は **256/256 一致、mismatch 0** だった。生成物の `CURRENT_MC_VERSION` は `JavaMinecraftVersion::V_26_2`、`PacketId::to_id` の 26.2 field は `v26_2` である。

したがって、今回確認できた範囲に確実な packet ID/state/direction 不整合はない。推測による ID 変更、生成物の手編集、正式コードの packet mapping 修正は行っていない。

### ライセンス・出典

- 公式 Mojang server JAR は一次検証専用に一時取得し、リポジトリへ保存・再配布していない。
- ViaVersion の数値確認は MIT licensed upstream source の参照のみで、ソースのコピーはしていない。既存の `assets/NOTICE.md` の条件を変更していない。
- Minecraft Wiki は protocol/data の二次照合に使用し、公式 JAR 内 `version.json` を一次根拠とした。

## Recommended Next Steps

1. B 担当の connection 実装は、`status -> handshake -> login -> configuration -> play` の state ごとに上表の direction/ID を使用する。特に configuration の `select_known_packs=14/7`、`registry_data=7`、`finish_configuration=3` を 26.1 の値で流用しない。
2. payload 実装では packet ID mapping と field schema を別の証拠として扱う。今回 `assets/packet/26_2_packets.json` が検証済みでも、field codec の正しさや client 接続成功は未確認である。
3. codegen 実行時は `CARGO_TARGET_DIR` を外部一時領域に設定し、`cargo run -p pumpkin-codegen -- packet` の結果として変更されるのは `crates/pumpkin-data/src/generated/packet.rs` だけかを `git status` で確認する。生成物を手修正しない。
4. 次の実装後に、26.2 client の packet trace と server/client log を保存して、ID mismatch と payload decode error を分離して調査する。特に login clientbound の `LOGIN_FINISHED` alias と play clientbound の `LOGIN` は名前が似るため、state を混同しない。
5. world 担当は、今回一次確認した `world_version=4903` を `DataVersion` の根拠に使えるが、level version `19133`、chunk/NBT round-trip、registry payload は別途検証結果を記録する。
