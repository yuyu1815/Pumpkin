# 26.2 command vanilla policy / digging authority gate

## Findings

今回の担当は、既存の `26.2-command-vanilla-policy.md` と
`26.2-digging-authority.md` の実行ゲートである。production source の追加変更はせず、
owned change は `player_action.rs` の real-client test、`state.rs` の ACK-first assertion と本書に限定した。

- Signed command は `JavaClient::handle_signed_chat_command` で ACK を
  `state::apply_last_seen_update` により parse/signature handling より先に commit する。
  secure (`allow_chat_reports=true`) では signable argument の空 entry、unknown、missing、
  署名失敗を実行へ降格しない。reports-disabled のみ unsigned seam を許可する。
- Digging は `JavaClient::handle_player_action` の実 client/player/world path を通す。
  STOP-only、`may_build=false` の START、matching START state でも vanilla 0.7 cutoff 未達の
  STOP は block mutation を起こさず、authoritative block state は block restore の値を保つ。
- ACK、block restore、STOP cutoff の期待値は現行実装の出力合わせではなく、上記2文書と
  26.2 official bytecode の独立した契約から固定した。timeout 延長や現状値への期待値変更はしない。
- helper predicate だけの mining test は残さず、`player_action_uses_real_client_mining_authority_and_stop_cutoff`
  を real `JavaClient` + `Player` + `World` + loopback TCP client fixture として実行する。
