# 26.2 再現検証ハーネス

## Findings

- 対象は Java Edition 26.2 / protocol `776`。既存の根拠は `assets/packet/26_2_packets.json`、`crates/pumpkin-data/src/generated/packet.rs`、`crates/pumpkin-protocol/src/java/**` である。26.2 の packet mapping を新規発明せず、ハーネスは起動時に既存 JSON を読み、status/login/configuration/play の重要 packet ID が期待値からずれていないことを検査する。
- 実装した `tools/compat-26_2/protocol776_harness.py` は Python 標準ライブラリだけで動く。
  - status: handshake(protocol 776, next state 1) → status request → JSON の `version.protocol == 776` 検査 → 64-bit ping/pong の値一致。
  - offline login smoke: handshake(next state 2) → Login Start(name + UUID) → Set Compression の threshold 検査 → Login Success の UUID/name/property/session UUID を厳密に decode → Login Acknowledged → Configuration Client Information → Known Packs 空応答 → Configuration Finish 応答 → 最初の Play frame。
  - configuration/play の keep-alive は payload 長を厳密に検査し、受信した `i64` をそのまま応答する。configuration/play ping も既知 packet の `i32` として応答する。
  - server の `Disconnect` を受けた場合は reason string を decode して `protocol_disconnect` と記録する。ハーネス自身が socket を閉じるだけの結果は protocol disconnect 成功とは扱わない。
- `tools/pumpkin-fuzzer/src/main.rs` は既存の重複候補だが、`make_handshake_packet()` が protocol `769` (1.21.4) を固定し、random payload を送る fuzz/stress tool である。protocol 776 の互換 smoke test や offline login の構造検証の代替にはしなかった。
- status/login の frame は次を守る。
  - packet length / decompressed data はそれぞれ Pumpkin の `MAX_PACKET_SIZE = 2,097,152`、`MAX_PACKET_DATA_SIZE = 8,388,608` 以下。
  - VarInt は最大 5 bytes。truncated、負の length/id、empty packet data を拒否。
  - compression 有効後は `data length == 0` の raw packet と zlib packet を区別し、宣言した uncompressed length、zlib stream の終端、trailing data を検証。
  - outgoing packet も同じ上限を検査し、threshold 以上の raw packet だけ zlib 圧縮する。compression packet 自体は threshold が有効になる前に送られる。
- これは本物の Minecraft client ではない。registry NBT、update-tags、Join Game、chunk、resource pack、chat signing 等を解釈せず、既存 26.2 mapping に存在する packet の payload を opaque に通過させる部分がある。したがって `play_frame_observed` は protocol framing/state smoke の成功であり、vanilla client 接続成功・first chunk・完全互換を意味しない。

### toolchain / 容量 / 低ディスク build 方針

今回の確認値:

- `RUSTUP_TOOLCHAIN=1.97.1 rustc --version`: `rustc 1.97.1 (8bab26f4f 2026-07-14)`, exit 0。
- `RUSTUP_TOOLCHAIN=1.97.1 cargo --version`: `cargo 1.97.1 (c980f4866 2026-06-30)`, exit 0。
- `py --version`: Python `3.11.9`, exit 0。
- `java -version`: Java `21.0.5`, exit 0。公式 26.2 metadata が要求する Java runtime major `25` には不足するため、official JAR 後段試験には Java 25 を別途用意する。
- `Get-PSDrive -Name C`: used `759,182,274,560` bytes、free `239,892,545,536` bytes（約 223.4 GiB free）。既存 investigation の測定値 224G とほぼ一致。
- stable toolchain の自動同期 (`rustc --version` / `rustup toolchain list`) は 20--30 秒制限で exit 124 相当の timeout になり、1.98.1 components を同期中だった。1.97.1 を明示すれば上記の compiler/cargo と metadata は利用可能。stable の同期を再試行しない。

低ディスク時は `CARGO_TARGET_DIR` を repo 外の専用 temp に設定し、最初に `cargo check -p pumpkin-protocol --locked`、次に必要 package の `cargo test -p ... --locked` を一つずつ実行する。debug/release/LTO と workspace 全体の並列 build は避け、各 command 前後の `Get-PSDrive C` と target サイズを記録する。server run directory も repo 外にする。公式 client/server JAR は target、`tools/compat-26_2/`、git working tree に置かない。

### official 26.2 比較試験の取得・hash・license 方針

既存調査で確認済みの official metadata:

- manifest: `https://piston-meta.mojang.com/mc/game/version_manifest_v2.json`
- 26.2 metadata: `https://piston-meta.mojang.com/v1/packages/987b91a95ae93b3bb78cc14d6e0bbd31bad08d59/26.2.json`
- server.jar: 60,894,273 bytes、SHA-1 `823e2250d24b3ddac457a60c92a6a941943fcd6a`
- client.jar: 39,193,383 bytes、SHA-1 `2dc72797acbc1b63fc16a11c4ac393605f453754`
- metadata package SHA-1: `987b91a95ae93b3bb78cc14d6e0bbd31bad08d59`

後段で取得する場合の例（公式 metadata の URL を使い、保存先は repo 外の private temp、再配布しない）:

```powershell
$meta = Invoke-RestMethod 'https://piston-meta.mojang.com/v1/packages/987b91a95ae93b3bb78cc14d6e0bbd31bad08d59/26.2.json'
$dir = 'C:\Temp\minecraft-26_2-official'
New-Item -ItemType Directory -Force $dir | Out-Null
Invoke-WebRequest $meta.downloads.server.url -OutFile "$dir\server.jar"
Invoke-WebRequest $meta.downloads.client.url -OutFile "$dir\client.jar"
Get-FileHash "$dir\server.jar","$dir\client.jar" -Algorithm SHA1
(Get-Item "$dir\server.jar").Length
(Get-Item "$dir\client.jar").Length
```

取得時に URL、metadata package hash、取得日時、実測 byte 数、SHA-1 を evidence に記録し、期待値と一致しなければ起動・比較を中止する。Mojang/Microsoft の EULA、公式 launcher/account の利用条件、試験者のライセンス権限に従う。JAR、asset index、公式 assets、client log はこの repository に commit・再配布しない。`docs` には hash/URL/日時だけを記録し、必要なら管理外のアクセス制限された temp を試験後に削除する。公式 client は本ハーネスの成功判定には使わず、vanilla client 比較試験を別の evidence として扱う。
