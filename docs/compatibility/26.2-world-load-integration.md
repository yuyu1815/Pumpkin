# 26.2 world load failure Anvil integration

対象: Java Edition 26.2 / protocol `776` / world data version `4903`

## Findings

実 Anvil temporary fixture を、既存の `ChunkFileManager<AnvilChunkFile<ChunkData>>` → `io_read_work` → `GenerationSchedule::receive_chunk` 経路へ通した。mock の分類関数だけではなく、実ファイルを読み、worker の `RecvChunk` を scheduler の terminal branch へ渡している。

検証した fixture は次の5種類である。

- 正常 Anvil entry: `ChunkData::empty(0, 0)` を既存 Anvil writer で保存。worker は正常な `RecvChunk::IO(Chunk::Proto(...))`（uniform lighting の既存 relight 条件により `Features`）を返し、scheduler holder に chunk が入った。
- slot missing: 8192-byte zero header。worker は `RecvChunk::IO(Chunk::Proto(...))`、stage `Empty` を返した。
- malformed compression: 正常 entry の sector 2 の compression byte を `0x7f` に変更。worker は `RecvChunk::LoadFailure` を返した。
- malformed NBT: 正常 entry の compression byteを uncompressed (`3`) にし、payload先頭を不正な `0` に変更。worker は `RecvChunk::LoadFailure` を返した。
- region header error: region fileを8191 bytesに切り詰めた。worker は `RecvChunk::LoadFailure` を返した。

破損3 fixtureでは scheduler 受領後に以下を確認した。

- `running_task_count == 0`
- failure holder が保持されるが `holder.chunk == None`
- `holder.current_stage == StagedChunkEnum::None`
- public loaded chunk が存在しない
- `save_all_chunk(true)` が save batch / IO lock を生成しない
- DAG node / ready queue / `waiting_for_chunks` が空で、failure後に後続taskを再開しない
- fixture region の SHA-256 が読み取り前後で同一

正常 / missing では scheduler が worker の `IO` result を受領し、holder に chunk を保持した。missing は生成入口へ進む `Proto Empty` であり、payload errorをMissingへ降格していない。

region header error の4座標 batch（`(0,0)`, `(1,0)`, `(0,1)`, `(1,1)`）では、全4座標について座標一致した `RecvChunk::LoadFailure` が1件ずつ返ることを確認した。worker の座標単位 fetchと `ChunkFileManager::fetch_chunks` の全座標 terminal response 契約により、worker response欠落による待機を再現しなかった。

### 既存コードへの修正

本 integration 追加で Rust production logic の変更は行っていない。追加 APIもない。既存の `io_read_work`、`ChunkFileManager`、`GenerationSchedule::receive_chunk` を test-only scheduler harness から呼び出した。scheduler harnessは `#[cfg(test)]` 内に限定し、実 scheduler threadと同じ holder/task/result fieldsを使っている。

### 未確認事項

- このテストは failure holder に対する `save_all_chunk(true)` の送信なしと原本 hash不変を確認する。実 write workerを起動した save/unload end-to-end は別試験であり、本試験では起動していない。
- `process_unload_queue` の private lifecycleを実 scheduler threadで直接駆動する試験は未追加。ただし failure holderの `chunk=None` と `save_all_chunk` の非到達条件は本試験で確認した。
- generation DAGの successor再開防止は既存の `terminal_cancel_nodes` regression test（zero-radius descendant）で分類・graph stateを確認している。本 Anvil fixtureでは target stageを `Empty` とし、破損 payloadから generation taskを作らない境界を確認した。
- 最終確認: C: free `239707668480` bytes、停止閾値 `32212254720` bytes（30 GiB）を上回った。`cargo`/`rustc`/`pumpkin` の残存プロセスは0件。`git status --short --branch` は先行agent変更と本docs/既存world差分を保持しており、reset/clean/commitは未実行。

## Recommended Next Steps

1. 実 scheduler threadで複数座標の `region header error` を同時要求し、外部観測可能な unload/shutdown completion と合わせて確認する。
2. `process_unload_queue` と shutdown save を実 worker込みで接続し、failure holderが save channelへ入らない件数を専用 test instrumentationなしで確認できる形を検討する。
3. batch-oriented FileIOの性能影響（同一 region 32/256座標）を安全性テストと分離して測定する。
4. 既存 docs の未確認範囲どおり、retry/quarantine policy、region salvage、実 vanilla 26.2 client接続は別タスクとする。
