# 26.2 fix round validation — world corruption / protocol boundary / inventory scope

対象: Java Edition 26.2 / protocol `776` / world data version `4903`

## Findings

### World corruption review F-1: 解消

`GenerationSchedule::drop_node` の通常成功経路を load failure cancellation に流用せず、`GenerationSchedule::terminal_cancel_nodes` を追加した。

- failure の直接 root と、失敗座標の read area に入る非 in-flight node を root にする。
- root から outgoing edge を辿る非 in-flight descendant を closure として terminal cancellation する。
- cancellation では successor の `in_degree` を減らさず、queue へ再投入しない。
- stale queue entry、`waiting_for_chunks`、holder の task/occupied slot も closure に合わせて除去する。
- 実行中 descendant は強制停止しない。in-flight との同時成立は本変更で証明していないため、境界として残す。

これにより、失敗 chunk `A` を直接読む `B:Surface` を止めた際に、read radius `0` の `B:Carvers` が `drop_node` 経由で queue に解放される経路を閉じた。`Carvers -> Features` のようなさらに後続の descendant も同じ closure で止まる。

### World liveness / error termination: 追加修正

`ChunkFileManager::fetch_chunks` と `io_read_work` の結果契約を強化した。

- region open failure は batch の先頭座標だけでなく、要求された全座標へ terminal `LoadedData::Error` を返す。
- `ChunkNotExist` は channel close で表さず、各座標の `LoadedData::Missing` を返す。
- worker が channel close を観測した場合は `Missing` に黙って降格せず、`ChunkReadingError::IoError("chunk loader closed without a terminal outcome")` を `RecvChunk::LoadFailure` として送る。
- `RecvChunk::LoadFailure` は Proto/Level を作らず、holder の `chunk=None` を維持する。unload/save の source path は `chunk` が `None` の failure holder を save batch に入れない。

これで、正常な新規 region の Missing と、unexpected early close/contract violation の error を区別できる。TempDir Anvil の実 payload fixture、hash 不変、scheduler 受領までの integration test はまだ追加していないため、その範囲は未検証である。

### Retry / unload の限定判定

LoadFailure 直後の同一 holder に対する自動 retry loop は存在せず、今回も retry を自動追加していない。明示的な unload→再入場や level transition が同じ破損 entry を再読する場合の backoff/quarantine/rate-limit policy は未実装であり、今回の完成範囲に含めない。これは「retry storm 全体を解消済み」とは報告しないための明示的な残タスクである。

failure holder の `target_stage` は LevelChannel の旧 stage 契約を保つため残すが、`current_stage`/`dependency_stage`/`chunk` は terminal state にする。実 unload/save の end-to-end fixture は未実行で、source inspection と既存 save 条件に基づく判定である。

### Inventory 反証の限定範囲

`pumpkin-inventory` の 30 unit tests は成功したが、反証できたのは oak log → oak planks（通常 shaped recipe、output count `4`）を player 2x2 / crafting table 3x3 の実 `on_slot_click` → `quick_move` → `insert_item` → result callback 経路へ通した範囲だけである。partial stack、空き slot、full inventory、複数材料の内部反復を含む。

この結果から remainder（milk bucket/cake 等）、component/transmute、special/dynamic recipe、recipe book、stack size 1、実 world drop entity lifecycle、vanilla 26.2 client packet/UI 全体は反証できない。これらは未修正・未確定の INV-03 等として分離する。

### Protocol boundary

今回の protocol source を再コンパイルし、serverbound count boundary と uncompressed premature EOF の全 package test を実行した。count は signed negative、payload-fit、protocol max を allocation 前に拒否し、frame decoder は宣言 body 未達 EOF を受理しない。compressed trailing/stream-end の未確認候補は変更していない。
