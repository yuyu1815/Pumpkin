# Minecraft Java 26.2 / protocol 776 protocol boundary fix

## Findings

### NET-COUNT: serverbound collection count を allocation 前に拒否

対象は次の serverbound protocol codec である。

- `crates/pumpkin-protocol/src/java/server/play/chat_command_signed.rs`
  - symbol: `SChatCommandSigned::read`
- `crates/pumpkin-protocol/src/java/server/play/set_game_rule.rs`
  - symbol: `SSetGameRule::read`
- `crates/pumpkin-protocol/src/java/server/play/edit_book.rs`
  - symbol: `SEditBook::read`; 既存の `min(max_pages)` を silent truncation から
    checked negative/protocol/payload bound へ変更

修正前は、wire の signed `VarInt` を `as usize` に変換し、そのまま
`Vec::with_capacity` に渡していた。負値 `-1` は 5 bytes の VarInt で表現でき、
allocation 前の拒否がなかった。

修正後は次の順序になった。

1. `usize::try_from` で負値を `ReadingError::Message` として拒否する。
2. packet payload slice の **count 読取り後の残り bytes** を取得する。
3. 各 entry の最小 wire size から導いた上限を超える count を
   `ReadingError::TooLarge` として拒否する。
4. 上記を通過した count だけ `Vec::with_capacity` に渡す。

導入した根拠付き最小サイズは以下であり、恣意的な固定件数上限ではない。

| packet | 1 entry の最小 wire size | 判定 |
|---|---:|---|
| `chat_command_signed` argument signature | 257 bytes | 空文字列の長さ VarUInt 1 byte + signature 256 bytes |
| `set_game_rule` entry | 2 bytes | key/value の空文字列長 VarUInt 各 1 byte |
| `edit_book` page | 1 byte | page の空文字列長 VarUInt 1 byte。さらに protocol の既存 max pages (26.2: 100) を適用 |

chat command / game rule は `count > remaining_bytes / minimum_entry_bytes` の場合だけ
拒否する。edit book はこの payload-fit 判定に加えて、既存 protocol max pages
（26.2では100）を超える count を拒否する。合法な client の count を低い任意値へ
切り詰めず、packet の実残量と既存の field codec bound（command 256 UTF-16 chars、
argument name 16 UTF-16 chars、通常 String 32767 UTF-16 chars、signature 256 bytes）に
従う。

既存の process-wide 境界は変更していない。

- `MAX_PACKET_SIZE = 2,097,152`
- `MAX_PACKET_DATA_SIZE = 8,388,608`
- `VarInt` 最大 5 bytes

実呼出しも確認した。`SChatCommandSigned::read` は
`crates/pumpkin/src/net/java/mod.rs:930-938` で signed command の通常 command
処理・fallback より前に呼ばれる。`SSetGameRule::read` は同 `mod.rs:1349-1350`
で permission handler より前に呼ばれる。`SEditBook::read` も同 `mod.rs:1166-1167`
で book mutation handler より前に呼ばれる。このラウンドでは signed chat の認証本体、
command permission、他の net state は変更していない。

### NET-FRAME: 非圧縮 frame の宣言長未達 EOF を受理しない

対象は `crates/pumpkin-protocol/src/java/packet_decoder.rs` の
`TCPNetworkDecoder::get_raw_packet` である。

既存 decoder は `Take(packet_len)` から packet ID と payload を読み、payload read
loop が `bytes_read == 0` になると単に loop を抜けていた。そのため、TCP 接続が
EOF になった時点で宣言 body より短い `RawPacket` を返す可能性があった。

修正後は read loop の実読込み量 `total_read` と宣言 payload 長
`payload_len_hint` を比較し、一致しなければ
`PacketDecodeError::FailedDecompression` を返す。TCP がまだ open で分割された
残りを待てる場合は、`AsyncRead` の通常の pending/read 待ちを保持する。つまり、
短い read を EOF と誤認せず、接続 EOF のみを malformed frame として拒否する。

圧縮 threshold の既存境界修正は変更していない。特に
`raw_packet_length >= threshold` の判定と、既存 regression test
`reject_uncompressed_packet_at_compression_threshold` を保護した。

compressed zlib stream の trailing bytes / stream-end の厳密な frame 消費は今回
変更していない。監査資料で候補として挙がったが、`BufReader<Take<...>>` と
`ZlibDecoder` の read-ahead/remaining-body の実挙動をこのラウンドで反証する実測を
しておらず、確定した uncompressed premature EOF と混同して無理に修正しない。

## Migration / Investigation Notes

### 再現 test の入力と期待結果

allocation を実際に巨大化させる probe は行わない。以下の test は、count を
読むだけの小さい payload で allocation 前の reject を検査する。

`pumpkin-protocol` package の後続実行対象:

```text
java::server::play::chat_command_signed::tests::rejects_negative_signed_command_argument_count
java::server::play::chat_command_signed::tests::rejects_signed_command_count_that_cannot_fit_payload
java::server::play::chat_command_signed::tests::accepts_signed_command_with_wire_fit_argument_signature
java::server::play::set_game_rule::tests::rejects_negative_game_rule_entry_count
java::server::play::set_game_rule::tests::rejects_game_rule_count_that_cannot_fit_payload
java::server::play::set_game_rule::tests::accepts_game_rule_entries_with_wire_fit_count
java::server::play::edit_book::tests::rejects_negative_book_page_count
java::server::play::edit_book::tests::rejects_book_page_count_above_protocol_limit
java::server::play::edit_book::tests::accepts_book_page_count_that_fits_payload
java::packet_decoder::tests::decode_uncompressed_frame_split_across_reads
java::packet_decoder::tests::reject_uncompressed_frame_on_connection_eof
java::packet_decoder::tests::reject_uncompressed_packet_at_compression_threshold
```

count tests の入力は以下である。

- signed command: 空 command + timestamp 0 + salt 0 + count `-1` または
  `i32::MAX`。巨大な Vec は作らない。
- game rule: count `-1` または `i32::MAX` のみ。entry payload は作らない。
- edit book: page count `-1` と protocol limit 超過を page allocation 前に拒否する。
- 正常系: signed command は 1 signature（256 bytes）、game rule は 1 entry、book は
  payload に収まる 1 page。

frame tests は `TCPNetworkDecoder` そのものを `tokio::io::duplex` に接続する。

- `decode_uncompressed_frame_split_across_reads`
  - length/id を先に書き、writer を一度 yield してから payload を書く。
  - stream が open の間は decoder が残りを待ち、`id=1, payload="ab"` を返す。
- `reject_uncompressed_frame_on_connection_eof`
  - declared body length 3 に対して id + payload 1 byte だけを書き、writer を
    shutdown する。
  - decoder は `Ok(RawPacket)` ではなく
    `Err(PacketDecodeError::FailedDecompression(_))` を返す。

### 実行した確認

このラウンドではユーザー指示に従い、`cargo`、`rustup`、build、server 起動、
巨大 allocation probe、malicious TCP 外部 probe は実行していない。編集前に次を
ソース読取りで確認した。

- `git status --short --branch` の初期状態は既存の
  `packet_decoder.rs` / `anvil.rs` / `player.rs` tracked diff と、既存の
  `.pi/`・`docs/`・`tools/` untracked 領域。これらを reset/clean していない。
  作業中の後続 status では `pumpkin-inventory`、`pumpkin-world` の別 tracked diff も
  観測されたが、所有範囲外として保持し編集していない。
- 既存 `packet_decoder.rs` の compression threshold `>=` 修正と regression test は
  変更せず保持した。
- `MAX_PACKET_SIZE`、`MAX_PACKET_DATA_SIZE`、String/slice bound、VarInt 最大長、
  実 dispatcher 呼出しを確認した。
- `git diff --check` は終了コード 0。`rustfmt --check` は実行開始時に rustup の
  stable channel sync（`rustfmt --version`）へ進み、20秒 timeout になったため、format
  pass/終了コードは未取得。cargo/rustup の再試行はしていない。
- 26.1 layout/schema への変更や依存追加、root manifest 変更は行っていない。

未実行のため、test pass、Rust compile、clippy、実 server の kick/close 観測、
allocator の panic/OOM 種別は未確認である。
