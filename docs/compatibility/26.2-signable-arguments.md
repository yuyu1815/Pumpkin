# 26.2 signed command: signable argument の lossless parser 基盤

## Scope

この段階は `crates/pumpkin-command/` 内の pure parser contract だけを対象にする。
RSA、session、chain index、last-seen/ack、dispatch、fallback、permission policy、world
state は変更しない。signable argument の抽出結果は署名検証へ接続していないため、production
side effect はない。

## 公式 26.2 の根拠

Mojang 26.2 server JAR の static bytecode (`C:/Temp/minecraft-26_2-inner.jar`) を実行せず
確認した。`net.minecraft.commands.arguments.SignedArgument<T>` は `ArgumentType<T>` の
marker interface であり、`SignableCommand.ArgumentVisitor` は parsed argument の型が
`SignedArgument` を実装している場合だけ採用する。採用時の value は
`ParsedArgument.getRange()` を元の command string に適用した raw substring である。
node name は argument node の `getName()` であり、typed result の再シリアライズや正規化は
行わない。

26.2 JAR に含まれる `net.minecraft.commands.arguments` の top-level argument type を
`javap` で確認した結果、この一次仕様で `SignedArgument` を実装する production type は
`net.minecraft.commands.arguments.MessageArgument` だけだった。`EntityArgument`、
`GameProfileArgument`、`ComponentArgument`、数値・resource・selector 等を名前や文字列
性質だけから signable と推測していない。Pumpkin の既存 argument types には現時点で
`MessageArgument` 相当の登録 type が確認できないため、production command を一律に変更
せず、次の登録時に明示できる opt-in metadata として実装した。

参照した static artifact:

- `C:/Temp/minecraft-26_2-inner.jar`
- `C:/Temp/javap-signable-parse.txt`
- `C:/Temp/javap-signed-command-core.txt`
- official symbols: `SignedArgument`, `MessageArgument`, `SignableCommand`,
  `SignableCommand$Argument`, `ArgumentVisitor`

JAR の static inspection は vanilla の実 runtime/client round-trip の証拠ではない。

## 実装 API

### opt-in metadata

`crates/pumpkin-command/src/argument_builder.rs` の
`RequiredArgumentBuilder::signable(self) -> Self` が argument node を明示的に signable
として登録する。default は `false` であり、通常の `StringArgumentType` を含む全 type は
signable ではない。

`crates/pumpkin-command/src/node/mod.rs` の
`ArgumentNodeMetadata::signable: bool` が attached tree に保持される。これは公式の
`SignedArgument` marker を Pumpkin の node model に対応させた metadata で、argument
name、typed result、client-side parser、permission などから推測しない。

### lossless extraction

`crates/pumpkin-command/src/node/dispatcher.rs`:

```rust
pub struct SignableArgument {
    pub name: String,
    pub value: StringRange,
    pub node: NodeId,
}

impl SignableArgument {
    pub fn raw_value<'a>(&self, input: &'a str) -> &'a str;
}

impl ParsingResult {
    pub fn signable_arguments(&self) -> Option<Vec<SignableArgument>>;
}
```

- `value` は元の command input に対する Rust/UTF-8 **byte** range (`start..end`) である。
  Java/Brigadier の `StringRange` は UTF-16 code-unit index なので、これは同じ数値座標では
  ない。後続の net dispatch が Java range を必要とする場合は `raw_value(input)` を正本に
  して別途 UTF-16 座標を計算し、`value.start/end` を Java offset として送ってはならない。
- `raw_value(input)` はその UTF-8 byte range をそのまま slice する。quoted delimiter、escape、Unicode
  の UTF-8 bytes、greedy の空白を除去しない。署名本文に渡す候補はこの raw substring だけである。
- `node` は parse tree 内の `NodeId` であり、redirect をまたいでも実際に parse された
  argument node identity を保持する。
- `name` は node metadata の command-tree name である。
- typed `ParsedArgument.result` は署名対象へ使わない。
- parse が input 全体を消費せず error を持つ場合は `None`。完全 parse で signable node
  がない場合は `Some(Vec::new())` であり、これは正当な first-class result である。
- root context と redirect child context を parse path 順に巡回する。failed branch の
  partial range は返さない。

## 追加した pure tests

`crates/pumpkin-command/src/node/dispatcher.rs` の完全修飾 test symbol:

- `node::dispatcher::signable_tests::ordinary_string_argument_is_not_signable_by_default`
- `node::dispatcher::signable_tests::quoted_escaped_unicode_argument_keeps_the_original_utf8_range`
- `node::dispatcher::signable_tests::multiple_arguments_preserve_order_and_typed_normalization_is_ignored`
- `node::dispatcher::signable_tests::greedy_argument_covers_the_remaining_raw_input`
- `node::dispatcher::signable_tests::redirect_keeps_signable_argument_node_identity_and_path_order`
- `node::dispatcher::signable_tests::parse_failure_does_not_expose_partial_signable_ranges`

確認している入力要点:

- ordinary string は default で抽出されない。
- `🎃` と `é`、quoted string、escaped quote を含む raw range は UTF-8 byte boundary
  を保持する。テストでは Java UTF-16 code-unit count と異なることも確認し、UTF-8 range と
  UTF-16 range を混同しない契約を明記した。
- `007` は typed integer が `7` になっても raw value は `007` のまま。
- 複数 signable arguments は parse path 順に返る。
- greedy argument は残りの raw text と内部空白を全て含む。
- redirect の child context から node identity と argument value を失わない。
- unterminated quoted input は partial signable range を返さず `None` になる。

## 検証境界と未確認事項

`RUSTUP_TOOLCHAIN=1.97.1 CARGO_TARGET_DIR=C:/Temp/pumpkin-target-26_2-next
CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0 CARGO_BUILD_JOBS=2 cargo test --locked
-p pumpkin-command -- --nocapture` は exit `0`、unit **85 passed / 0 failed**、doctest
**5 passed / 0 failed**。Rust source-level pure contract と official JAR の static evidence
を確認したが、vanilla 26.2 runtime の packet round-trip、署名検証成功、kick/report UI、
chain state 消費は確認していない。

特にこの段階では signed-command の **network dispatch 未接続**である。`SChatCommandSigned`
は既存の通常 command text handlerへ渡されるだけで、`ParsingResult::signable_arguments()`
を署名本文、RSA/session/last-seen/ack、permission/fallback policyへ接続していない。
したがって production command はまだ signable verification を実行せず、今回の API は side
 effect-free の opt-in parser foundation に留まる。
後続接続時の不変条件:

1. signed packet の signature body content には `SignableArgument::raw_value` の raw
   substring だけを渡し、typed value/stringify/whole command を使わない。
2. `name` は signature entry の lookup key であり、signature bytes に追加しない。
3. 現在の `crates/pumpkin/src/command/argument_builder.rs` の wrapper API は ownership
   boundary のため未変更である。production command registration へこの opt-in を公開する
   場合は、後続 owner が `RequiredArgumentBuilder::signable` の forwarding を追加する。
4. parse failure または signable list の `None` を通常 dispatch/fallback の成功扱いに
   しない。
5. `Some(Vec::new())` は signable argument がない valid parse として保持する。
6. この抽出 API に RSA、session index、last-seen、ack state の side effect を追加しない。
7. `value` は UTF-8 byte range、公式 Brigadier range は UTF-16 code-unit range であり、net
   dispatch 接続時に座標体系を取り違えない。
