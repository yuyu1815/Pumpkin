# Minecraft Java 26.2 compatibility: initial investigation

- 調査目的: Minecraft Java Edition 26.2 client が接続して遊べる Rust server の実装計画を作る。
- 調査時点: 2026-09-18（Mojang manifest の HTTP Date も同日）。
- 方針: 26.2 を未確認の別版へ置換しない。公式 JAR はダウンロード・リポジトリへの再配布をしない。
- 状態: 実装前の足場調査。完全互換・プレイ成功はまだ検証していない。

## 3. 26.2 の版情報（確認済み事実と未確認事項）

### 公式 Mojang manifest

取得した公式 URL:

- manifest: <https://piston-meta.mojang.com/mc/game/version_manifest_v2.json>
- 26.2 metadata: <https://piston-meta.mojang.com/v1/packages/987b91a95ae93b3bb78cc14d6e0bbd31bad08d59/26.2.json>

manifest の `26.2` entry は `type=release`、`releaseTime=2026-06-16T12:03:33+00:00`、SHA-1 `987b91a95ae93b3bb78cc14d6e0bbd31bad08d59` である。manifest の最新 release/snapshot は調査時点では `26.3` だったが、目標は 26.2 のままとする。

公式 26.2 metadata の抜粋:

| 項目 | 確認値 |
|---|---|
| client artifact | `client.jar`, 39,193,383 bytes, SHA-1 `2dc72797acbc1b63fc16a11c4ac393605f453754` |
| server artifact | `server.jar`, 60,894,273 bytes, SHA-1 `823e2250d24b3ddac457a60c92a6a941943fcd6a` |
| Java runtime | major version 25 (`java-runtime-epsilon`) |
| asset index | id `32`, SHA-1 `d6540f46a8fec49e45fb7312cdcf401a8e4e15ff`, index size 586,366 bytes |
| main class | `net.minecraft.client.main.Main` |

ここでいう client/server は Mojang metadata の配布物を指す。JAR 本体、asset index 本体、公式 assets は取得していないため、ローカル実物の manifest/JAR 内検証（protocol/data version、packet layout、実際の起動）は未実施である。

### protocol/data version の相互確認

| 値 | 根拠 | 判定 |
|---|---|---|
| Java protocol `776` | Pumpkin `JavaMinecraftVersion::V_26_2`、ViaVersion の `ProtocolVersion.java` の `v26_2 = register(776, "26.2")`、Minecraft Wiki の 26.2 ページ | 3 系統で一致 |
| world/data version `4903` | Pumpkin `MAXIMUM_SUPPORTED_WORLD_DATA_VERSION` / Anvil `WORLD_DATA_VERSION`、Minecraft Wiki の 26.2 ページ | 2 系統で一致 |
| Java level version `19133` | Pumpkin の `MAXIMUM_SUPPORTED_LEVEL_VERSION` | Pumpkin 内の実装値。公式 metadata では未提示のため、JAR/公式 report で未検証 |

参照先:

- ViaVersion（MIT）: <https://raw.githubusercontent.com/ViaVersion/ViaVersion/master/api/src/main/java/com/viaversion/viaversion/api/protocol/version/ProtocolVersion.java>
- Minecraft Wiki の版ページ（外部の信頼できる protocol/data 集約）: <https://minecraft.wiki/w/Java_Edition_26.2>
- PrismarineJS/minecraft-data: <https://github.com/PrismarineJS/minecraft-data>

PrismarineJS/minecraft-data では調査時点に `data/pc/26.1/version.json`（protocol `775`）は存在したが、`data/pc/26.2/` は存在しなかった。このため、26.2 の packet/data source として同リポジトリを勝手に代用していない。26.2 向けの同プロジェクト側更新が公開された後に差分検証候補とする。

再現コマンド（JAR本体を落とさず metadata/raw source だけ取得）:

```text
# official manifest / 26.2 metadata
curl -fsSL --max-time 30 https://piston-meta.mojang.com/mc/game/version_manifest_v2.json
curl -fsSL --max-time 30 https://piston-meta.mojang.com/v1/packages/987b91a95ae93b3bb78cc14d6e0bbd31bad08d59/26.2.json

# ViaVersion の登録値
curl -fsSL --max-time 30 https://raw.githubusercontent.com/ViaVersion/ViaVersion/master/api/src/main/java/com/viaversion/viaversion/api/protocol/version/ProtocolVersion.java | grep -n -E '26\\.2|776'

# minecraft-data の公開状況
curl -fsSL --max-time 30 https://raw.githubusercontent.com/PrismarineJS/minecraft-data/master/data/pc/26.1/version.json
curl -fsSL --max-time 30 https://api.github.com/repos/PrismarineJS/minecraft-data/contents/data/pc
```

取得できなかった情報は「26.2 が存在しない」とは解釈しない。公式 manifest では release の存在を確認済みであり、未確認なのは JAR 内を解析した protocol/data/report の一次検証である。

## 4. 再利用候補、ライセンス、出典

優先順位は次の通り。

1. 既存 Pumpkin の 26.2 導入（`23e7992b2d...`）と generated code を再利用する。
2. `assets/packet/26_2_packets.json`、`assets/datapacks/26_2/`、`assets/viabackwards/` の既存管理データを、出典と NOTICE を保ったまま利用する。
3. protocol の比較・不足確認には ViaVersion の 26.2 登録値と必要なら MIT 条件のソースを参照する。ViaVersion の当該ソースは MIT header を持つが、ソースを Pumpkin にコピーするのではなく、数値と設計の出典として扱う。
4. `minecraft-data` は 26.2 データが未公開だったため、26.1 との差分観察に限定する。

ライセンス上の注意:

- Pumpkin server / codegen は root `LICENSE` の GPLv3。
- `crates/pumpkin-plugin-api` と `crates/pumpkin-plugin-wit` は MIT OR Apache-2.0。
- `assets/NOTICE.md` は Mojang/Microsoft assets、ViaVersion/ViaBackwards/ViaRewind、Geyser/Bedrock data の帰属・条件を分離して記載している。
- `assets/viabackwards/data/` の再利用条件は NOTICE の GPLv3 / MIT 記載を確認し、個別ファイルの由来を変更時の docs に残す。
- Mojang client/server JAR と公式 assets は再配布しない。必要な場合は管理外の一時領域に置き、URL・SHA-1・取得日だけを記録する。

## 5. ディスク、build 安全策、実験領域

確認値:

- C: 総 931G、使用 707G、空き 224G（76%使用）。
- `.git` 170M、`assets` 112M、`crates` 107M、`tools` 1.6M。
- `target/` は調査開始時に存在しなかった。
- `RUSTUP_TOOLCHAIN=1.97.1 cargo metadata --no-deps --format-version 1` は終了コード 0、workspace 20 packages。
- `rust-toolchain.toml` は `stable` 指定、workspace の `rust-version` は 1.96。stable の同期を試みた `rustup` は 20 秒制限で終了コード 124（1.98.1 の components を同期中）となった。これはコード失敗ではなく、現時点で stable toolchain が安全に準備済みとは確認できないという阻害要因である。

今回は `cargo build`、`cargo test`、`cargo clippy`、`cargo run`、release/LTO build を実行していない。大規模 build は後続で次の安全策を守る。

- まず `cargo check -p pumpkin-protocol` 等の小さい package 単位を 1 本ずつ実行し、`CARGO_TARGET_DIR` を専用の外部/無視領域へ設定する。
- protocol/data/world/server を同時に release build しない。生成物サイズと空き容量を前後で記録する。
- 公式 JAR は `C:/Users/yuzum/...` の管理外・非再配布の一時領域にだけ置き、必要量（client 約38 MiB、server 約58 MiB）と SHA-1 を再確認する。asset index の `totalSize` は約458 MiB相当であり、全 asset の取得は互換性に不要な段階では行わない。
- 実験用 Rust/packet capture/parser は `tools/compat-26_2/` に置き、正式 server code (`crates/`) と分離する。実験データは `artifacts/compat-26_2/`（gitignore対象）に置き、JARは保存しない。

## 7. 推奨する最初の縦断的互換目標と検証基準

最初の目標は「26.2 Java client (protocol 776) が、ローカル offline-mode の Pumpkin に接続し、status → handshake → login/configuration → Join Game → overworld の最初の chunk → position/keepalive → clean disconnect まで完了する」こととする。これはプレイ可能性の最小足場であり、完全互換ではない。次の段階で block break/place、movement collision、chat、online-mode を追加する。

合格条件:

1. client が protocol 776 で server status を表示し、server が誤って 26.3 や 26.1 と名乗らない。
2. 26.2 の login/configuration packet が client log の decode error なしに往復する。
3. server が `DataVersion=4903` の world を読み書きし、round-trip 後の NBT/chunk で対象フィールドが保持される。
4. client log、server log、可能なら packet trace を保存し、再現コマンド・commit hash・toolchain・終了コードを記録する。
5. online-mode、全 packet、全 gameplay、mod/plugin、Bedrock bridge は別の検証項目として未確認/失敗を明示する。

この記録の時点では上記 1--5 の実接続・JAR内解析・full build は未実施であり、「26.2 完全互換」とは報告しない。
