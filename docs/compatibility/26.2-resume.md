## Migration / Investigation Notes

### 安全な次回 build / 起動 / 接続試験

次回は直列に、まず package 単位の check、次に offline server 起動、最後に harness を実行する。以下は **記録用の未実行コマンド**。各段階で空き容量、process、終了コードを記録し、失敗したら次段へ進まない。

1. repo 外 target と run directory を用意する。既存 directory がある場合は削除せず、別名を選ぶ。

```powershell
$repo = 'C:\Users\yuzum\Desktop\mine_rust_server\Pumpkin'
$run = 'C:\Temp\pumpkin-26_2-offline-next'
$target = 'C:\Temp\pumpkin-target-26_2-next'
New-Item -ItemType Directory -Force $run,$target | Out-Null
@'
[networking.java]
enabled = true
address = "127.0.0.1:25565"
online_mode = false
encryption = false

[networking.bedrock]
enabled = false

[telemetry]
enabled = false
'@ | Set-Content -Encoding UTF8 "$run\pumpkin.toml"
$env:CARGO_TARGET_DIR = $target
$env:RUSTUP_TOOLCHAIN = '1.97.1'
```

2. 最初の軽量 check（workspace build の代わり）:

```powershell
Push-Location $repo
try {
  cargo check --locked -p pumpkin-protocol
  $exit = $LASTEXITCODE
  $bytes = if (Test-Path $target) { (Get-ChildItem $target -Recurse -File -Force | Measure-Object Length -Sum).Sum } else { 0 }
  "cargo_check_exit=$exit target_bytes=$bytes"
  if ($exit -ne 0) { exit $exit }
} finally { Pop-Location }
```

3. check が成功し、C: free bytes が十分な場合だけ、run directory を cwd にして server を起動する。`cargo run` は重いため、並列実行しない。

```powershell
Push-Location $run
try {
  cargo run --manifest-path "$repo\Cargo.toml" --locked -p pumpkin
} finally { Pop-Location }
```

server log に bind 成功が出て `127.0.0.1:25565` を listen している間だけ、別 shell から次を実行する。

```powershell
Set-Location 'C:\Users\yuzum\Desktop\mine_rust_server\Pumpkin'
py tools\compat-26_2\protocol776_harness.py --mode status --host 127.0.0.1 --port 25565 --timeout 5
py tools\compat-26_2\protocol776_harness.py --mode login --host 127.0.0.1 --port 25565 --timeout 40 --wait-for-keepalive
```

期待する smoke の観測値は status の `protocol=776`、`status_pong=pass`、login の `login_success`、`known_pack_reply=true`、`play_packets>=1`、`real_client_compatibility=not_claimed`。これは protocol smoke の合格であり、vanilla client の接続・chunk描画・遊べることの証明ではない。ハーネスは TCP を閉じるため、`protocol_disconnect` が返らなければ clean server disconnect の証拠にもならない。

4. server を停止した後に、target bytes と free bytes を再測定し、`git status --short --untracked-files=all` と `git diff --check` を確認する。run/world/log は repo 外または `tools/compat-26_2/artifacts/`（ignore 対象）に限定し、JARをrepoへ置かない。
