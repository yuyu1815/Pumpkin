# 26.2 signed-command production seam

## 根拠と実装境界

- 公式 26.2 static inspection (`docs/compatibility/26.2-signable-arguments.md`) で
  `SignedArgument` の production type は `MessageArgument` のみ。Pumpkin ではその実コマンド相当の
  `/say`、`/me`、`/msg`・`/tell`・`/w`、`/teammsg`・`/tm` の message/action 引数だけを
  `RequiredArgumentBuilder::signable()` で opt-in した。
- 通常の string/greedy、selector、typed argument、`tellraw` の component、ban/kick/team の
  理由・表示名は signable にしていない。
- `SChatCommandSigned::read` は公式 argument signature 上限 `8` と trailing body を strict に扱い、
  decode failure を `SChatCommand::read` へ fallback しない。実 dispatch は
  `JavaClient::handle_play_packet` の signed packet 分岐一箇所から専用
  `JavaClient::handle_signed_chat_command` へ進み、parse 結果の raw UTF-8 range と packet argument
  name の集合を対応付ける。
- 完全 parse (`Some`) かつ signable argument なし (`Some([])`)・signature entry なしだけを、player
  source の通常 permission path へ渡す。decode/parse failure (`None`)、trailing body、unknown/
  duplicate/missing name は unsigned fallback しない。
- RSA、profile session、last-seen/ack、inbound chain は未接続。signable argument がある packet は
  検証なしで実行せず、offline/unsigned の通常 `SChatCommand` path は変更していない。
