## Findings

### Chat owner token and runtime fixture

`ChatOwnerToken` in `crates/pumpkin/src/net/chat/state.rs` is a per-`Player`
capability (`Arc` owned by `Player`, `Weak` held by the sidecar) with an atomic
retired bit. `reset_inbound_state`, `clear_inbound_state`, and
`verify_and_commit` compare the token by `Arc::ptr_eq` and also check the session
UUID. A retired token cannot reset state; a late old verify returns
`ChatStateError::LifecycleMismatch`; an old clear cannot remove replacement
state. `verify_and_commit` does not create missing state.

`Server::add_player` publishes the replacement before retiring older same-UUID
world owners. `World::remove_player` removes an exact `Arc<Player>` and retires
only on `Disconnect`, not `DimensionTransfer`. The runtime fixture
`net::chat::state::tests::duplicate_login_runtime_preserves_new_owner_transfer_and_bounded_state`
uses real `Server`, `World`, `EntityTracker`, `CachedStatus`, loopback-backed
`JavaClient`, duplicate UUID publication, delayed old reset/verify, transfer,
old disconnect, new-owner retention, and 32 add/disconnect cycles. This is
independent of the pure state helper tests.

The review found no evidence that the old token can clear or break the new
owner's sidecar in the covered production path. Remaining boundary: the token
API is crate-internal and binds identity through the `(UUID, session, Arc token)`
triple at each call; it is not an externally authenticated command identity.
The fixture does not prove Mojang session certificate/RSA acceptance because
`allow_chat_reports=false`.

### Reconfiguration review and narrow correction

The strict envelope parser correctly rejects a Configuration clientbound ID
absent from `assets/packet/26_2_packets.json`; mapped packets outside the decoded
subset are `needs_review`, not silently accepted as semantic compatibility.
Critical Registry Data, Update Tags, Known Packs, Finish, keep-alive/ping, and
Disconnect bodies have bounded/end-of-frame checks.

A concrete false rejection was found: `Update Enabled Features` is present in
the mapping but the repository's protocol-776 Configuration path omits it
(`crates/pumpkin/src/net/java/login/known_packs.rs` and
`net/java/config/known_packs.rs` send it only for versions older than 1.20.5).
The tracker previously required it before Known Packs and in `require_complete`.
The narrow fix makes it optional: if present it must be first and valid; its
absence is legal for protocol 776. A regression test covers the omitted path.

The diagnostic/readiness events improve correlation, but they do not by
themselves establish the root cause of the earlier `pending_bytes=24,
closed=true` baseline failure. Reader/writer/listener ordering and server close
reason still require repeated real-TCP observation.
